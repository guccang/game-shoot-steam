# 营地移动帧耗时排查（2026-10-27）

输入为用户导出的 `forest-performance (3).json`，诊断版本 `2026-10-27-sixty-fps-v4`。日志设备字段为 Windows Chrome 153、DPR 1、1080×921，不能作为华为 Mate 50 Pro 的实机测试结果。本次输出版本为 `2026-10-27-camp-movement-v5`。

## 日志中的问题

导出时已暂停，分析使用保留的最近 120 个游玩帧。该窗口没有敌人、投射物和战斗特效，平均 25.87FPS，逻辑约 24.58Hz；目标仍为逻辑 25Hz、渲染 60Hz。

| 阶段 | 平均耗时 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 整帧 CPU | 27.75ms | 44.8ms | 126.7ms |
| Canvas 提交 | 13.17ms | 19.9ms | 108.7ms |
| 实体绘制 | 6.72ms | 10.0ms | 12.6ms |
| 面板更新 | 9.12ms | 16.5ms | 20.1ms |
| 邻里面板 | 5.36ms | 11.8ms | 14.9ms |
| 地面 | 1.60ms | 0.4ms | 94.2ms |

父阶段包含子阶段，不能将表中数值全部相加。Canvas 提交是 CPU 侧耗时，不是 GPU 执行完成时间。该窗口另有一次 72.1ms 地面补建；整份日志的地面缓存记录 16 次同步未命中。

居民气泡原来每帧先隐藏，再重写文字、显示、读取宽高。在包含全局对白显隐选择器的正式界面中，这些写入会反复使样式和文字布局失效。闲聊出现与消失时，开销也会随之变化，不能只用怪物数量解释营地帧率。

地块预热原来仅能使用整帧 12ms 以内的余量。日志中多数帧超过这个阈值，移动前方的预热容易停滞；队列还会为已经可用的白天地块先补夜色。走到新块时，绘制入口必须同步完成剩余步骤，形成顿挫。

## 本次修改

- 居民与故事短句保持可见节点，只提交变化的文字、语义属性和坐标。样式比较使用上次提交值，避免 CSSOM 小数精度归一化导致反复写入。
- 气泡复用本帧场景容器几何；只有真正被对白遮挡、画外或空间不足时隐藏。闲聊间隔内不再测量布局和遍历候选人物。
- 邻里热点取消重复显隐，画外热点不先显示再隐藏。
- 白天地面优先准备缺失路面，然后补齐夜色；夜间和首次入场仍准备完整昼夜纹理。
- 必需地块预热获得至少 0.75ms 的请求预算，通常仍使用原有最多 2ms 的帧余量。生成器单步不可中断，实际切片可能超支，继续由 `maxSliceMs` 如实记录。

未改变逻辑帧率、时间倍率、角色动作、地面图元、纹理精度和缓存容量。首次入场和传送冷缓存仍可能同步缺块，本次没有承诺消除所有长帧。

## 验证与限制

在独立工作树用 4185 端口测试，保留已占用的默认 4175 服务。移动夹具从 (740,1940) 出发，以正式键盘输入往返，不替换 `game.update`。对比基线为 `daa0dbc`；测试期间同机整体负载存在变化。

| 本地移动结果 | 修改前 | 修改后首次 | 修改后最终复测 |
| --- | ---: | ---: | ---: |
| 最近 120 帧 FPS | 37.75 | 40.23 | 36.49 |
| 整帧 CPU 平均 | 20.04ms | 18.72ms | 20.29ms |
| 窗口内地面最大耗时 | 260.3ms | 0.7ms | 2.4ms |
| 整段移动新增同步未命中 | 7 | 2 | 1 |

这是有限本地样本。地面同步补建显著减少，但平均 FPS 没有稳定提升，不能据此宣称达到 60FPS。表中最大耗时属于最近 120 帧窗口，未命中数量则覆盖整段移动；两者统计范围不同。

同一正式 DOM 下的气泡独立对照，最终每次更新由 4.95ms 降至 0.10ms，40 次稳定更新的 DOM 变更由 320 次降至 0。此前两次对照为 7.25→0.14ms、7.91→0.28ms。该结果验证具体开销的减少，不等同于全场帧率收益。
