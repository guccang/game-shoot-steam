# 世界观与主线重设计：把森林还给大家

日期：2026-10-31。状态：设计稿；本次交付不修改运行时任务、资产、数值或存档。下文的章节、世界变化和结局是待实现设计，不是现有功能说明。后续主线重做以本稿为目标，旧实现与验收记录继续保留作迁移依据。

## 一句话讲清游戏

**荆棘王占领了森林之心，封住大家回家的路。你是晴叶营地的巡林员，要接回失散的伙伴，带着大家打回森林深处，夺回家园。**

玩家长期记住的使命只有一句：**把森林还给大家。** 每次行动回答一个具体问题：今天谁需要我，我要替他们解决什么，完成后我们离家又近了多少。

参考马里奥、塞尔达的方向是让目标、对手、目的地和冒险成果一眼能懂。保留本作猫咪巡林员、森林邻居、枪械和载具的身份，不照搬人物、圣物、王国或救公主结构。不引入前世、预言、阵营百科、碎片收集和幕后第二反派。

## 世界只讲四件事

1. **这里原本是大家共同的家。** 猫咪、叶蝠、野猪和史莱姆一起生活。河岸有渡口，林中有木场，晴叶营地负责巡路、修理和接应。枪械、机械伙伴和车辆本来就是巡林员的工具。
2. **森林深处有一棵被叫作“森林之心”的古树。** 它让林中的植物正常生长。荆棘王占据古树，用它催生荆棘，封路、围住聚落，把家园变成自己的领地。森林之心是一个明确可抵达的地方，不是要收集的货币。
3. **荆棘王想让所有居民服从自己。** 他派部下占住渡口、木场和旧哨站。第一章就交代是谁做的、他在哪里、为什么必须阻止他；后续章节让玩家不断拆掉他的封锁。
4. **晴叶是仍能收留大家的营地。** 其他地方有人回不来，有人等不到药，有人被围住。你先救眼前的人，再把分散的伙伴组织起来，最终夺回古树。

敌我是行为和阵营的区别。铁牙、小夜、枭爵、阿团仍是邻居，不能因为外观与野外敌人相同就被写成该消灭的种族。敌方领主使用独立身份，不把铁牙或枭爵当作主线反派。昼夜照常交替；黑夜本身不是邪恶，通关也不取消夜晚。

## 玩家为什么愿意负责

主角是玩家选中的猫咪，是晴叶的巡林员。没有血统资格，也没有别人都不能做事的设定。开局先完成一次救援，再主动接下承诺：

> 雪团：营地里的人齐了，可小夜还没回来。
>
> 主角：他走哪条路？我去接他。
>
> 小夜获救后：河对岸还有人。那里的灯也灭了。
>
> 主角：先带你回家。然后，我们去接他们。

责任感来自看得见的人、兑现的承诺和留下的改变。居民会修桥、送药、守门、侦察；玩家负责打通最危险的地方。不会每个村民都站着等主角办完全部事情，也不靠“你去玩支线就害死了大家”逼迫玩家推进。

开场约三分钟内让玩家知道：家园出了什么事、谁在作恶、眼前要救谁、最终要去哪里。先给可操作的救援目标；背景只需一幅现场景象和几句对白，不先讲长篇历史。

## 一条连续主线，六章十八个任务

章节按剧情因果顺序推进，任务在现场接续。完成一个阶段不必回告示牌领取下一项；只有故事确实要回营时才返程。下表每项都有实际完成条件，点击面板或播放对白不能代替世界事件。

| 章 | 任务 | 玩家实际做什么，何时完成 | 给下一步留下什么 |
| --- | --- | --- | --- |
| 一 · 还有人没回来 | 1. 接回小夜 | 赶到断路处，击退围住小夜的敌人，与获救的小夜会合 | 小夜报告河对岸的求救；明确荆棘王是封路者 |
| 一 | 2. 带他回家 | 清开撤离沿线的阻截，和小夜抵达营地入口；玩家独自先到不算完成 | 失散的伙伴真实回营，玩家有了第一个必须保护的人 |
| 一 | 3. 守住晴叶 | 在营地门口击退追兵，保护撤离入口直到所有归队者进入 | 营地能接收更多居民；小夜交出渡口求救的位置 |
| 二 · 河对岸的求救 | 4. 让对岸听见 | 抵达旧中继站，守住薄荷的修复作业，接通实时求救 | 确认伤员所在的渡口，并知道旧桥被毁 |
| 二 | 5. 把药送过去 | 护送药箱抵达对岸救护点，现场交接；可以借船过河，也可以清开绕行路线 | 伤员得到救治，恢复行动的船工愿意协助撤离 |
| 二 | 6. 留住这个渡口 | 击退占据码头的敌方头目，保护居民撤到安全集合点 | 渡口成为救援补给点；众人得知木场还有修桥材料 |
| 三 · 把回家的路接起来 | 7. 接应木场 | 清开木场入口，救出被困工人，确认人员到齐 | 铁牙能组织搬运，用现有木料修回通往内林的桥 |
| 三 | 8. 护送最后一车 | 护送载着桥材的运输队通过两个危险路段，直到人和货到达桥头 | 桥材真实到位；不要求玩家购买或驾驶指定载具 |
| 三 | 9. 桥那边也是我们的家 | 守住桥头施工点，阻止敌人破坏修复，桥完成后走到对岸会合 | 通往内林的道路恢复；发现敌人在旧哨站集结 |
| 四 · 夺回旧哨站 | 10. 打掉封路据点 | 清除哨站外的封锁队，拆除控制路障的装置 | 救援队能接近被困的巡林小队 |
| 四 | 11. 一个也不落下 | 找到被困队员与机械伙伴，清理撤离通道，确认全部返回哨站 | 队员带回森林之心入口的位置；机械伙伴此后参与守备 |
| 四 | 12. 守住反攻的落脚点 | 击败夺回哨站的敌方队长，守住修复中的观测台 | 荆棘王知道大家准备反攻，转而袭击晴叶营地 |
| 五 · 这次换我们守住家 | 13. 回去接应大家 | 经已修好的桥返回晴叶，清出受袭的营地入口，接应滞留居民 | 前面修桥的成果直接帮助救援；伙伴各自就位 |
| 五 | 14. 晴叶不会再退 | 完成一次有剧情编排的营地防守，守住入口和避难点 | 居民靠共同协作挡住主力，打开反攻窗口 |
| 五 | 15. 点亮信号，大家出发 | 抵达高处信号点，清除拦截并发出集结信号，收到渡口与哨站回应 | 各地伙伴明确承担接应任务；森林之心的进攻路线确定 |
| 六 · 把森林还给大家 | 16. 一起打到森林之心 | 从旧哨站出发，突破最终道路上的封锁，抵达古树前 | 伙伴维持补给与退路；玩家进入最后的战场 |
| 六 | 17. 击败荆棘王 | 在正式战斗中躲过荆棘封路、冲击和召援，利用恢复阶段击败荆棘王 | 反派被击败，控制古树的装置失去守卫 |
| 六 | 18. 回家了 | 亲手解除古树束缚，确认主路恢复；沿已恢复的路线回营参加欢迎 | 完成“大家能够安全回家”的开场承诺，主线正式结束 |

每章约三个有意义的任务，不以十八次接取、十八次汇报拆碎流程。表内会合、交接、抵达与守点是任务阶段，不再展开成独立的功能签到清单。

二、三、四章的场景重点分别是“渡过隔断”“保护移动中的人和货”“夺下并守住敌方据点”，第五章让曾经被救的人反过来保护营地，第六章完成主动反攻。避免六章都采用“到一个点、清三波、拿回执”的同一流程。

## 关卡必须把故事做出来

**救援有同行的人。** 小夜和运输队需要实际移动、等待和抵达判定。队伍受阻时有清楚提示；不得仅在目的地刷出角色便宣布护送完成。危险阶段失败从本段安全点重试，不永久杀死邻居。

**夺回的地方持续属于大家。** 渡口开放补给、桥能够通行、哨站有伙伴值守。离开章节、刷新游戏和重玩后仍保持已取得的永久成果。关键安全路线不再原样刷回封锁主路的剧情敌人；野外岔路和独立挑战继续保留战斗。

**角色确实有分工。** 雪团负责安置与清点，薄荷负责通信与线路，铁牙组织修桥，枭爵安排防守，小夜传递路况。机械伙伴进入友方守备编排。可以用可靠的固定岗位行为表达协作，不必扩张成任意同行的开放世界 AI。

**终章有一个真正的最终敌人。** 荆棘王占据古树前的独立战斗场，动作围绕“把路据为己有”展开：可预警的荆棘封路、沿空隙闪避的冲击、暴露破绽的恢复。必须保留正式蓄力、释放、恢复和死亡表现。不能拿旧广播上传或一次普通清场作为主线终局。

**结局兑现开场。** 开场小夜独自被困，结尾小夜站在通行的路旁迎接玩家。雪团说“这次，人齐了”；主角回答“走，回家吃饭。” 欢迎结束后回到可继续游玩的营地，昼夜、种地和邻里生活照常。

目前的章节场景在退出时会清理，第三章原搬运也没有独立运输车 AI。因此持续道路变化、同行护送和荆棘王战斗都属于新增实现需求，不能只改对白就称为已完成。

## 把功能安排回合理的位置

| 内容 | 新位置 | 主线中的使用规则 |
| --- | --- | --- |
| 地图、移动、射击、闪避、交互 | 第一次实际需要时出现的短提示 | 走到救援地、击退敌人才算目标；打开地图不算主线任务 |
| 枪械购买、升级、部件、改装 | 工坊成长与可选整备建议 | 不再以某枪几级、买某件装备作为剧情通行证 |
| 载具和机械伙伴体验 | 工坊演练、装备委托；主线可提供借用 | 有水路就给可用船或绕行路径，有空中捷径就给临时载具；不要求永久购买 |
| 种花、农田、邻里午饭与画册 | 营地生活支线 | 保留温度与人物关系；不在渡口求救和反攻中间强制等作物成熟 |
| 无尽远征、时空塔、守护祭坛、足球、消防 | 独立玩法与各自委托 | 主线不要求逐一进入、通关或看完教学；现有玩法继续可用 |
| 野外清缴、反复兽潮 | 持续战斗和资源来源 | 主线使用明确地点和原因的独立遭遇，不把累计刷怪次数当剧情进度 |
| 章节奖励与装备资格 | 经济成长层的独立配置 | 章末首先反馈救了谁、哪里恢复；资源和资格是附带结果 |

基础操作提示不阻塞任务结算；已会操作的玩家可以直接完成目标。难度围绕主线提供的基础装备与可借工具定标，养成改善体验，但不能把刷资源付费整备变成隐含前置。现有购买资格规则单独核对，不能把当前已放开的购买限制又加回来。

主线中的“守住晴叶”是有开始和结束的专门事件。可以复用营地兽潮能力，但不是让玩家随便打一场旧模式并回来打勾。主线里的救火、种植或飞行也只有在剧情确实需要时使用，不为覆盖功能而安排。

## 任务文案与手机提示

任务卡使用“章名、当前目标、为什么”三层即可，不新增复杂的 PC 界面。例如：

> 河对岸的求救
>
> 把药送到对岸救护点
>
> 渡口还有伤员等药。船工会在岸边接应你。

战斗时只显示短目标与必要进度，例如“守住营地入口”“接应居民 2/3”。长原因放在展开详情。地图和地面导航始终指向当前真实目标；教学按钮与支线建议不能抢占主线箭头。

接任务用“那边还有两个人没回来，帮我接他们”，交任务用“人齐了，船今晚能开”。把“完成一次体验”“获得购买资格”“前往功能入口”留给相应的工坊和独立玩法说明。任务按钮保持中文和手机触控标准。

### 运行结构与存档边界

- 主线只有一个当前目标来源。可让成长任务层承担章节摘要与导航、故事状态机承担阶段执行，但二者共用新任务 ID 和同一提交事件；不能维护两份可以各自完成的主线。
- 章节内部复用现有 `travel`、`wave`、`defense`、`boss`、交互和对白动作；新增队伍护送、持久桥梁/据点状态、最终反派与结局状态。不更换 HTML/CSS/JavaScript、Canvas 2D、坐标体系或正式武器绘制器。
- 新剧情使用独立版本与新 ID；旧 `progress.mainline` 及 `progress.story.chapters` 迁移前完整保留。新存档直接进入新开场；旧存档首次进入新主线也从救援开场开始，继承装备和资源，不用旧教学记录冒认新剧情完成。
- 正在进行的旧故事先提供“继续当前故事”或“暂存并开始新主线”；不静默丢弃检查点。旧任务待领取的奖励保留一次领取通道，历史账本避免重复发奖。
- 已开放的装备资格与旧整组谢礼不回收。特别检查 [equipment-quests.js](../src/config/equipment-quests.js) 对 `sunleaf-04`、`sunleaf-05` 的购买资格依赖，以及 [story-posts.js](../src/config/story-posts.js) 的旧故事合集；不能迁移后让新玩家失去取得资格的途径。新主线对应第四、五章完成也提供等价资格，旧章入口继续可重玩。
- 世界永久成果由新剧情账本投射，章节临时敌人、队伍和特效仍按会话清理。重玩不撤销桥梁和据点，不重复发章奖；失败只回退当前未完成阶段。
- 新主线奖励另做预算，避免把原 42 项奖励简单叠加到 18 项上；本稿不擅自确定货币数量。正式实现时必须证明基础配置可通主线，无须先刷金币购买某型号。

## 实施顺序与设计验收

先实现第一章完整体验：救出小夜、实际带回、守住入口、回营相认。使用现有角色与场景能力验证任务因果和责任感，再扩展渡口、修桥与哨站，最后制作反攻和结局。第一章需要独立闭环，但不将它伪称为整条新主线已经完成。

新增古树、荆棘、桥的状态、敌方首领和动画前，执行 [美术资源生成标准](art-generation-standard.md)，建立 [美术任务单](art-generation-brief.md)。本次仅写叙事与流程设计，不生成或修改美术，不填造昼夜截图或游戏验收结果。运行界面继续遵守 [手机 UI 框架](ui-foundation.md)。

| 设计验收点 | 后续实际实现需要提供的证据 |
| --- | --- |
| 玩家能用一句话说清使命 | 开场试玩后知道“荆棘王占了家园，我要救人并夺回森林之心”，无需读百科 |
| 任务由剧情因果推进 | 不打开工坊、不买指定装备、不进娱乐玩法，仍能按十八项任务完成整条主线 |

| 章节成果留在世界里 | 救援后居民回营；渡口、桥、哨站在退出章节、刷新与重玩后持续正确 |
| 反派和结局兑现目标 | 正式战斗击败荆棘王，解除古树束缚，实际出现归家收束；不能只换结算文案 |

| 旧档不丢、不重发、不卡资格 | 新档、旧任务进行中、待领奖、已通关、旧故事暂存以及已得装备资格的迁移专项检查 |
