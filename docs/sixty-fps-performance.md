## 提交了什么，成本在哪里

Canvas 命令采样保留了 10 个稀疏样本；所有样本每帧均值中，`fill` 约 366 次 / 0.62ms，`stroke` 约 244 次 / 0.28ms，`beginPath` 约 424 次 / 0.28ms，`drawImage` 约 25 次 / 0.25ms。第 2700 帧的 `fill` 累积达 1.9ms，`drawImage`、`ellipse`、`stroke` 各约 0.8ms。

这些调用来自地面、标牌、光影、实体和特效的路径填充、描边、贴图及状态切换。并不存在一个每次都最慢、删除后即可翻倍的 Canvas 指令；样本的计时粒度也不适合把单次 0.1ms 排成精确榜单。采样不包括离屏画布、属性赋值和 GPU 光栅化，不能把上述数值相加当作完整渲染成本。

浏览器调用栈进一步定位到 `task-navigation.js` 的 `offsetHeight` 读取，单次 `UpdateLayoutTree` 可达约 6ms，涉及 170 个元素。它既包含任务按钮自身修改的影响，也支付了前面面板写入引起的样式重算。只移动这一读取会转移统计归属，不能降低总成本。

## 本轮实现

- 寻路开关、清缴标签、剧情状态和入职对白只在值改变时写 DOM；减少相同文本节点重建、父容器类名及显隐重复提交。
- 主线对白先计算最终显隐，避免每帧先隐藏再显示；执行任务阶段不再先投影一个最终还要隐藏的 NPC。
- 隐藏的短提示不测量 HUD；提示出现后继续按真实卡片尺寸定位。NPC 投影复用同帧容器几何。
- 场景热点离屏时跳过无用坐标写入，重新入镜立即采用当前坐标；仍保留 44px 触控下限。
- 表现数组和 Map 复用独立镜像，清除已删除成员；只处理历史中存在的连续数值，查询函数绑定复用。权威状态、25Hz 逻辑、射速和动作时钟不变。
- 诊断增加 `render.panels.mainline.navigation/objective/guide` 分项，供下一份日志继续定位。

开发期间主分支恢复了原 SVG／程序 UI，本分支已同步该改动，不恢复已撤回的 PNG。此任务没有增加资源文件或纹理缓存。

## 对照结果与限制

本地正式应用夹具：1080×921、相同玩家位置、激光武器、260 个持续特效、正式 25Hz 更新和插值，预热 3 秒、运行 6 秒，报告最后 120 帧。无敌和推迟刷怪仅用于固定场景，性能阶段没有替换 Game.update。

最新主分支 `7b0fb11` 作为旧代码对照；通过浏览器路由返回 Git 导出的原模块，其余资源与新版共用同一服务。最终连续对照如下：

| 指标 | 最新主分支对照 | 优化后 |
| --- | ---: | ---: |
| 主线界面平均 | 3.20ms | 1.19ms |
| 全部每帧面板平均 | 4.64ms | 2.84ms |
| 插值平均 | 1.18ms | 1.10ms |
| Canvas 平均 | 7.53ms | 10.48ms |
| CPU 总平均 / P95 | 15.18 / 19.70ms | 17.03 / 28.50ms |
| 实际 FPS | 55.12 | 47.29 |

主线开销下降约 63%，但这组整帧结果没有改善，Canvas 波动抵消了收益，不能将组件降耗直接宣称为稳定提升 FPS。合入相同最终代码后的另一轮样本为 55.97fps，CPU 平均 13.95ms、P95 19.70ms，主线 0.89ms。两次最终版本样本约 47～56fps，仍不能验收“稳定 60fps”。

同一页面交替运行旧、新插值的 8 组独立对照，最终均值为 1.076ms → 0.714ms，下降约 34%；这是插值微基准，不代表整帧加速比例。稳定状态连续渲染任务开关 100 次，MutationObserver 记录 0 次冗余修改。

初期 PNG 版本还记录过 39～52fps 的样本，途中也有更慢结果；这些历史记录保留在输出目录，未混入上表。此处不将短时桌面样本外推为手机温度或半小时表现。

## 仍需解决的预算

优先复核新版真实兽潮日志中的 Canvas 特效／实体提交、低频 UI 刷新峰值，以及地面缓存同步缺页。原用户日志还记录到一次约 103ms 的地面提交尖峰，平均值无法揭示这种卡顿。
进一步缓存或裁剪必须验证实际覆盖率、动画连续性和画面差异，不能仅凭调用次数减少就认为收益成立。达到平均 60fps 之外，还需压低 P95 并留出热机余量；当前日志没有 GPU 完成时间或温度，无法据此认定热降频已经解决。
