# 敌人寻路逻辑帧优化（2026-11-09）

用户提供的 `forest-performance.json` 最近游玩窗口中，逻辑平均 66.41ms，敌人 AI 平均 64.27ms，占逻辑约 96.8%；敌人 AI 的 P95 为 613ms、最大 996ms。导出场景只有 3 只敌人。记录没有位置和函数调用栈，因此不能从附件单独确定是哪处地形。

在当前地图复现到：小山峰附近的绕行会建立含周边山峰角点的可见图，旧搜索在找到目标前精查大量无关长边。每条边仍按 8 单位步长检测地形，造成首次规划尖峰。

## 改动

- `src/physics/visibility-route.js` 提供惰性 A* 搜索。用距离下界排序候选边，出队时才精确判断通行；边失败后仍允许从其他父节点到达该点。
- 自然地形和聚落多角绕行接入同一搜索。保留各自原有节点、半径、地形采样、周期世界距离、路线缓存和聚落单角快捷路径。
- 不修改逻辑步频、攻击状态机、美术或绘制器。最短距离相同的多条路线可能选取不同角点。

## 本机对照

运行 `node scripts/benchmark-enemy-navigation.mjs`：固定前 12 处区域山地的第 5 座山峰，每处 3 只敌人，调用正式 `updateEnemies`，25Hz，每处首次更新后连续推进 50 步。初始化不计时；不含 Canvas、UI 和整帧其他逻辑。基线通过临时 Node 加载器将搜索恢复为修改前的完整图 Dijkstra，其余代码与数据相同。

| 指标 | 原搜索 | 新搜索 |
| --- | ---: | ---: |
| 首次敌人更新平均 | 211.45ms | 3.48ms |
| 后续敌人更新平均 | 0.744ms | 0.416ms |

首次更新平均耗时下降约 98.4%。这些数据不能当作原手机场景的整帧耗时，仍需在原设备重新导出性能记录。

## 针对性验证

执行 `node --test`，仅指定以下 7 个文件：`visibility-route`、`enemy-fence-path`、`cautious-pursuit`、`enemy-attack`、`terrain-coverage`、`jiuzhaigou`、`incremental-warmup`（均为 `tests/*.test.mjs`）。46 项中 36 项通过、10 项失败。

新增测试以 160 个确定性有向图对照独立全图最短路，覆盖失败边、不可达、周期距离；含 300 个远端角点的局部绕角只执行 3 次精确检查。绕栏真实移动、30/120Hz 扑击、安全区保护、大湖绕行、山峰间通行及预热一致性相关检查通过。

失败项在临时恢复旧搜索后全部复现：武器警戒范围 1 项、收招重叠 1 项、九寨沟布局/地被/旅行/碰撞/战斗 8 项。本次未修改这些既有问题；完整测试输出在本机临时目录 `forest-nav-new-tests.txt` 与 `forest-nav-old-tests.txt`。未运行全量测试，未进行手机实机或浏览器整帧验收。
