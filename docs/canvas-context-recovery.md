# 手机浏览器角色与树林丢失修复

## 原因与范围

用户提供的 `forest-performance(2).json` 记录运行约134秒和270秒时两轮Canvas上下文丢失，累计32条DOM画布丢失事件。主画布恢复后仍使用已失效的树木和角色离屏帧，因此树冠和猫身体消失，直接绘制的阴影、手持武器和载具仍能出现。该报告无法进一步区分内存压力和浏览器/GPU驱动重置。

本次修复绘图资源生命周期，不更换美术资源、角色帧、图层、镜头或游戏规则。

## 实现

- 主画布、DOM画布、离屏HTMLCanvas和OffscreenCanvas统一记录上下文代际；同一事件捕获与目标监听去重，不阻止浏览器默认恢复。
- 一批事件合并到绘制边界，失效并释放角色衍生帧、树木、地形、怪物、生活设施、剧情道具、天气、河流和室内纹理。原始PNG、动作轨迹、游戏存档、镜头和季节调度时钟保留。
- 主画布仍丢失时停止无效的绘制与缓存构建；首次加载遇到丢失时等待恢复，避免空视野进入地块调度。
- HUD头像、载具和农具图标的缓存签名随代际失效。独立演练场同时接入恢复。
- 角色48帧缓存淘汰时立即释放像素。已释放缓存迟到的恢复事件不会再触发重建，弱引用监听不阻止画布回收。
- 手机默认每季地面缓存从64块降至24块，昼夜层约28 MiB；两季各自有界，镜头拉远时以完整可见块数为最低容量，保持原分辨率。
- 诊断版本为 `2026-10-29-canvas-recovery-v9`，新增 `rendering.contextRecovery`，包含离屏事件及集中重建次数。

## 验证

新增3项Node测试通过；相关角色动画、品种、地面调度、季节双池、绘制流水线与风格测试共33项通过。风格测试另有1项既有失败，未修改主分支同样复现：`town-restoration.js` 新增的 `drawRestorationBuildCountdown` 未同步旧接口快照。本次未改写无关快照，未运行全量测试。

真实Chrome浏览器使用390×844与320×720视口验证。默认4175端口已被其他本地服务占用，本任务使用隔离的4176端口。

1. 等待正式游戏加载完成、角色原始图集就绪，记录固定姿态的角色和树木像素。
2. 清空Canvas像素存储，证明树冠变成0个非透明像素，猫从12320降到4135个非透明像素，仅手持部分等直接绘制内容保留。
3. 连续两轮发送丢失/恢复事件，每轮只执行一次集中重建。树木恢复6598个非透明像素、哈希183435892；角色恢复12320个、哈希2265613083，与故障前完全一致。
4. 验证游戏进度、玩家状态、动作时钟和镜头状态不变，旧地块与角色帧像素全部释放。
5. 只让一个离屏树图集失效，不发送主画布事件，验证下一帧自动重建并恢复相同像素。
6. 日景与夜景同屏检查角色、树冠和地面，页面无异常；移动地面预算为24。截图为冻结战斗的正式场景，仅测试样式隐藏暂停遮罩以便检查。

浏览器检查脚本：`tests/canvas-recovery-browser.cjs`。结果和截图保存在 `output/playwright/canvas-recovery/`，属于本地验收输出，不打入游戏发布包。

本测试模拟的是像素存储丢失与恢复事件，不是鸿蒙真机GPU故障；仍需发布后在原手机上复测长时间运行、前后台切换和重复恢复。
