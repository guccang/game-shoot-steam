# 森林巡游游戏美术资源生成标准

版本：1.1　制定日期：2026年10月21日　更新日期：2026年10月27日　适用范围：本项目后续美术生成、扩展、替换与验收。

当前已确认的美术方向是柔和的森林绘本风格：清楚的轮廓、有限的明暗色块、统一的落地关系，以及可供战斗的开放空间。后续资源应延续现有资产，不重新定义画风。单件素材质量与放入游戏后的整体效果必须同时合格。

本文面向美术设计、生成工具操作、动画制作及资源接入人员。执行一次具体任务时，复制[美术生成任务单](art-generation-brief.md)，填写当前阶段、类别、参考图、尺寸、锚点、分层和验收目标，再开始实现或生成；已有对应任务单时继续更新。

## 开发流程与阶段边界

与 [AGENTS.md](../AGENTS.md) 的“开发阶段美术实现与后续PNG替换”一致，默认流程为：**imagegen + 程序绘制 + SVG 实现动态效果与交互 → 实机确认 → imagegen 精修图片 → PNG替换与复核**。

| 阶段 | 实现方式与交付 | 验收重点 |
| --- | --- | --- |
| 动态效果开发 | 使用现有 HTML/CSS/JavaScript、Canvas 2D 和 SVG 完成分层、动作、状态、进度和交互；imagegen 辅助探索风格、生成参考或阶段性图片。交付可运行效果、源码、任务单与实机证据。 | 动作真实性、锚点、起停与暂停、数值和交互、手机昼夜同屏；按实际实现记录资源与缓存预算。 |
| 美术精修与PNG替换 | 动态效果确认后，用 imagegen 生成质量更好的图片，按已确认的 PNG 样式交付透明 PNG 或所需 PNG 图集，逐项接入正式绘制器。 | 比例与系列风格、裁切和透明边缘、锚点与分层兼容、加载和解码预算，以及替换前后的动作与交互一致性。 |

开发阶段不要求全部资产先转为 PNG，也不以最终图片齐备作为实现动态效果的前提。已声明使用的程序绘制、SVG 或阶段性图片可作为本阶段正式实现；后续 PNG 精修项在任务单中记为“后续阶段”，不得伪记已完成。用户明确要求本次直接生成或替换 PNG 时，执行该任务范围，并保留、验证已有动态逻辑。

PNG替换保持逻辑尺寸、锚点、分层、稳定标识和交互接口。数值、进度、导航、状态与动画时钟继续由程序控制，动态圆环和引导曲线仍可使用程序或 SVG；独立运动部件分开交付，不把动态效果烘焙成单张静态图片。既有猫身体真实连续帧、独立操枪、怪物动作、履带与旋翼合同继续执行。

本节统一后续任务的阶段与格式要求。下文历史补充及已完成任务单保留当时的实现证据，其中 SVG、WebP、PNG 等格式描述不构成所有新任务必须照搬的生产路线；已确认的资源按实际清单使用，进入专门替换任务时再精修对应资产。阶段性实现必须明确声明；任何已声明必需的运行素材缺失仍须明确失败，不能静默回退到原型来通过验收。

## 2 本轮改造的有效方法

| 原有问题 | 已采用的修改方法 | 后续应复用的原则 |
| --- | --- | --- |
| 地面像一整块底色，景物缺乏归属 | 草甸、林下、田埂、湿沙和浅水形成不同大色块 | 先建立地形分区，再放主体，最后补细节 |
| 树木遮住营地和麦田 | 疏开核心区树木，树冠整体避让入口和田前，外围成组保留 | 留白是构图的一部分，不能按空隙逐个补满 |
| 景物贴在地上，没有重量 | 明确亮面、背光面、接触影和投影，并拆分地面层与实体层 | 体积依靠明暗与落地关系，不能只增加表面纹理 |
| 山、湖和沙滩各自孤立 | 山脚草坡接湖岸，花石集中在过渡带，林缘包围局部 | 以景观组为交付和审查单位，同时保留可拆分部件 |
| 河岸和沙滩左右对称、宽度一致 | 两岸独立布置，沙湾有宽窄、岬角和开口 | 自然感来自有控制的不对称，不能靠高频噪声制造毛边 |
| 多个景点只有颜色区别 | 改变峰数、湖形、沙带节奏、树冠及树干结构 | 先做剪影差异，再做内部结构和配色差异 |
| 动作柔和与操枪机制互相牵制 | 猫身体使用正面连续帧，小手、枪械、后坐和枪口独立运行 | 身体表现与交互部件分别生产，以锚点和动作时钟接合 |
| 玩法入口依赖长篇文字 | 用主题插画、建筑剪影和少量标题表达，解释移至问号帮助 | 图片表达主题，程序文字表达规则和实时数值 |

制作先以**轮廓与比例 → 地形关系与留白 → 分层与锚点**建立可运行结构，随即实现动态效果与交互并进行实机检查；确认后再精修明暗、落影、材质与局部细节，生成并替换 PNG，复核遮挡、动作和整体效果。动作与交互验收贯穿两阶段，不等最终美术完成才开始。前一步有问题时，不用增加下一步细节掩盖。

## 3 统一视觉语言

### 3.1 视角与比例

采用现有三分之四俯视表现，能看到物体顶面及部分侧面，地面上的圆形呈压扁椭圆。角色以当前猫猫的画面高度和脚底位置作为比例尺，树、建筑、车辆都在同一运行时镜头下比较。

不自行引入另一套等距网格角度、透视消失点或俯视比例。不要根据截图的屏幕像素直接推算世界尺寸；镜头倍率、设备像素比和图集倍率必须分开记录。新资产先与现有同类资产并排，再决定尺寸。

### 3.2 轮廓与描边

主体轮廓圆润、厚实，复杂物体先概括为少量可辨认的大形。外轮廓比内部纹理清楚；深色描边随材质偏绿、灰绿或棕色，避免全场统一纯黑粗线。

以当前树、岩山和小摆件为参照，常见轮廓线宽约为 **1.7–2.5 个逻辑绘制单位**。这是现有资产的参考范围，不是所有输出图片的固定像素线宽；高倍导出应按倍率同比放大。最终以正常游戏缩放下是否协调为准。

### 3.3 配色与明暗

普通材质使用底色、暗面、亮面三个主要层次，局部可加小面积高光。大色块优先，纹理服务于材质识别。地面与背景降低对比，角色、武器、攻击预警和交互入口更醒目。

下表是当前代码使用的代表性色值，可用于生成提示和调色起点；同一系列的亮暗关系比逐像素锁定色值更重要。

| 材质 | 暗部或描边 | 中间色 | 亮部 |
| --- | --- | --- | --- |
| 阔叶树冠 | `#315C43`、`#387B54` | `#67A85E` | `#A5CB72`、`#D1E597` |
| 松针与深林 | `#285B4B`、`#28725A` | `#46976B` | `#82BB7C` |
| 暖色树叶 | `#82572F`、`#B37938` | `#DFAA4D` | `#F2CC6B` |
| 岩壁 | `#718672`、`#859587` | `#A4AD9B` | `#C0C3AD` |
| 木质摆件 | `#795F3F` | `#B68A51`、`#BE945A` | `#E0B777` |
| 湖水 | 深水 `#2C95B6` | 水面 `#329DBD`、`#49AFC3` | 浅水 `#8ACAC8` |
| 沙地 | 接壤土色 `#CEB47E` | 干沙 `#EBD09A` | 沙纹 `#FAE9C1` |

禁止为普通背景资产铺满金属反光、写实噪点、重渐变、强辉光或高饱和荧光色。能量、传送门和攻击特效可以使用局部强调色，但必须控制面积并保留轮廓。

### 3.4 光照与落地

白天统一表现为左上受光、右下偏冷的阴影。树冠亮顶与底部暗叶团分开，建筑区分屋顶受光面、侧墙和檐影，岩山区分平台、亮壁与暗壁。

落地关系分为三部分：

| 部分 | 用途 | 生产与接入要求 |
| --- | --- | --- |
| 本体暗面 | 表达形体转折 | 留在主体资源内，不能随地面投影单独漂移 |
| 接触影 | 把脚、树根、墙根压到地面 | 面积小、贴近接触点；需要随主体保持正确锚定 |
| 地面投影 | 表达高度和光向 | 与可遮挡主体分离，在角色之前绘制；避免烘焙进不透明背景 |

现有树木将小范围根部接触影一起烘焙，较大的投影由地面层绘制。新增资产沿用这一分工，接入时核对同一影子没有被重复画两次。

夜晚共用同一形体、锚点和材质层次，由现有夜色转换及场景色调统一处理。局部暖光与萤火虫只在适当位置强调，不把整张夜景简单压成黑色，也不为每个对象重新随机生成夜景轮廓。

## 4 各类资产的生成要求

### 4.1 树木与树林

每种树至少在树冠外形、树干或分枝、叶片组织中的两项有可辨差异。多个树龄变体在同一树种内部变化；不能把六种颜色作为六种树林。

| 树林 | 标识 | 必须保留的识别特征 |
| --- | --- | --- |
| 阔叶林 | `round` | 宽而连续的圆润树冠，冠内枝叉，亮顶与冷底影 |
| 云杉林 | `pine` | 向上收尖、层次错开的针叶冠，窄主干 |
| 白桦林 | `birch` | 浅色细干和短横纹，细分枝、较轻的小冠团 |
| 垂柳林 | `willow` | 横向展开的冠部和下垂叶束，拱垂枝形 |
| 枫树林 | `maple` | 带角状叶瓣的分组树冠，暖色叶面和显露枝叉 |
| 柏树林 | `cypress` | 细长直立冠团，主峰与侧枝形成竖向节奏 |

树林以疏密变化成组分布。营地、麦田前侧、建筑入口和沙滩主活动面保持开阔。避让以完整树冠及其摆动范围检查，不能只检查树干落点。新增树种仍保留风摆、受击、采集及原位再生的资源身份。

### 4.2 山体

山体用几块大岩壁与草顶组成，保留圆润的岩柱转折和少量缺口。侧面明暗清楚，碎石、苔草和藤蔓只作局部点缀。底座连接自己的草坡及少量花石，不能直接贴在裸露的背景色上。

| 山体 | 标识 | 结构差异 |
| --- | --- | --- |
| 草顶台山 | `mesa` | 宽主台、较完整草顶、低矮附石 |
| 错落双峰 | `twins` | 两个高度不同的主体，中间形成清楚凹口 |
| 石笋群峰 | `needles` | 多个细长峰柱，高度与前后位置错开 |
| 层叠台地 | `terraces` | 宽底座逐级收窄，平台有可见层次 |
| 横卧山脊 | `ridge` | 横向延伸的低中峰，形成连续起伏 |
| 环抱石冠 | `crown` | 两侧高柱围合较低中心，留出内部凹形 |

山顶的草不能漂浮在岩壁之外，藤蔓不能沿用固定高度而悬空。视觉凹口不自动代表可穿行通道：如需山洞或拱门，应另行定义碰撞和通路，不能只画一个洞就宣称可通过。

### 4.3 湖泊与河流

水域的外轮廓和逻辑水界共用数据。外缘浅水、中间水色及偏移的深水块形成层次，避免整齐等距的同心环。水纹低对比，白沫断续出现；不把每条水纹都描成与角色一样醒目的线条。

| 湖泊 | 标识 | 轮廓重点 |
| --- | --- | --- |
| 豆荚湖 | `bean` | 一侧饱满、一侧内收的不对称长圆形 |
| 月牙湖 | `crescent` | 明确的单侧凹湾和两端展开 |
| 蜿蜒长湖 | `ribbon` | 狭长、轻微弯曲，宽度有变化 |
| 三湾湖 | `clover` | 三个尺度不完全一致的湾部 |
| 水滴湖 | `pear` | 一端收窄、一端较宽的方向感 |
| 岩角湖 | `diamond` | 不规则转折和柔化的角部，不能画成标准菱形 |

河流两岸的沙宽、湾口、草岸与摆件独立组织。桥头和沿岸已有通路必须保留。水草、睡莲、石块的位置与水深和岸线有关，不能均匀撒满水面。

### 4.4 沙滩

沙滩由草沙交界、干沙、湿岸和浅水衔接。宽沙主要朝一侧展开，中央保持干净，摆件贴边分组。

| 沙滩 | 标识 | 宽窄节奏 |
| --- | --- | --- |
| 弧湾沙滩 | `crescent` | 单个连贯宽湾，两端收窄 |
| 双湾沙滩 | `twin` | 两个大小不同的沙湾，中部收腰 |
| 长岬沙滩 | `spit` | 局部伸出的狭长沙岬 |
| 扇形沙洲 | `fan` | 较宽展开的活动面，边缘缓慢收束 |
| 贝纹沙滩 | `scallop` | 总体弧形中出现少量局部凹凸 |
| 起伏沙丘 | `dunes` | 不对称沙丘轮廓，配少量弯曲沙脊 |

六类形态由轮廓和内部组织共同区分，颜色变化只作辅助。禁止镜像两岸、等宽包围整湖、锯齿毛边，以及把沙滩填满脚印、贝壳或装饰。

### 4.5 建筑与麦田

建筑首先保证屋顶、墙体、入口和底座四部分可辨。瓦片采用有节奏的搭接，屋檐下有暗面，墙根和石基接触地面；不同建筑依靠主轮廓和功能结构区分。门前踏石、小径或低栅栏把建筑接到道路，但不能围成堵住角色的封闭院落。

麦田分开生产田埂与可遮挡麦穗。田埂有亮顶和短土层断面，麦穗亮、茎根暗，排间与高度略有交错。保持大面积金黄色的整体读感，不以每根麦秆的写实细节取胜。麦穗按行参与深度排序，角色进入时应主要被前排遮住下半身。

### 4.6 小摆件与生态细节

栅栏、木堆、石簇、小花、芦苇、漂木和木凳采用相同视角、光向和描边。每个小组只服务一个关系，例如墙根石簇、田后木堆、草沙交界花丛或湖边漂木。

小摆件默认作为装饰，不因新增美术自动新增碰撞。需要可采集或可破坏时，在任务单中明确实体属性。萤火虫采用独立缓慢漂浮，集中在部分花丛和湖岸；不要将所有光点同步闪烁或画成恒定覆盖画面的亮雾。

### 4.7 猫猫、怪物与载具

猫猫保留当前身体比例与正面主体方案。六品种的脸型、耳型、毛发和毛色共同识别：橘猫的椭圆脸与尖耳、英短的圆脸小耳、美短的宽下颌、暹罗的楔形脸大耳、布偶的颊毛颈毛、孟买猫的圆耳与贴服短毛。修改局部外观不能破坏原有脚步、眨眼与表情。

怪物和载具与场景共用有限平涂、清楚外轮廓和柔和草木配色。普通怪、精英和领主需要体量或结构上的层级；攻击提示必须比环境装饰更易辨认。载具车体、炮塔、履带或旋翼按运行需要拆分，不能把驾驶员和枪械永久烘焙进车身。

### 4.8 玩法插画和界面资源

玩法插画用一个明确主体说明主题：传送门与选择、逐层上升的塔、需要守护的女神或祭坛。插画可以使用更完整的背景构图，但必须保持角色身份、配色和材质一致。

图片内不生成说明文字、数值、按钮、徽标或水印。标题、状态和交互由界面层负责；长解释通过问号图标按需展开。当前秘境卡片资源采用 768×512 WebP；新插画应先确定实际容器和裁切方式，再在主体周围留出安全区。场景贴图与卡片插画不得互相代替。

## 5 景观组合与活动空间

每组景观采用“主体地貌 + 过渡地面 + 次级地貌 + 边缘生态 + 少量摆件”的结构。主次必须清楚，次级景物不能把主体围成看不见的中心。

| 组合方式 | 衔接方法 | 必须留出的区域 |
| --- | --- | --- |
| 山体与湖泊 | 山脚草坡接近岸草地，花石偏向两侧 | 山脚到岸边的干地走廊 |
| 湖泊与宽沙滩 | 浅水、湿岸、干沙连续过渡，单侧展开 | 沙滩中央与进入草地的开口 |
| 山湖与树林 | 树种围绕整组景观变化，外围疏密过渡 | 主体剪影、角色穿行线与镜头视线 |
| 建筑与麦田 | 墙根、田埂、短栅栏及踏石连接道路 | 门前、田前和桥头 |

当前四境森林的四类目录支持 6×6×6×6 种类型搭配，该地图展示六组。类型可以自由搭配，但放置不能忽略道路、营地、河流和相邻地貌；安全空间不足时应缩小、调整或省略，不能为了凑数量堵路。

布局检查以逻辑轮廓、完整树冠、最高山顶和投影范围共同进行。当前生成器对同组山湖采用物理范围留距，对其他地貌使用更大的视觉避让；这些距离是现有地图实现参数，不直接转换成任意游戏的通用像素标准。

组合资产应可拆分并可按种子复现：地貌、草坡、沙带、摆件、树林及萤火虫锚点分别保存。湖面既是绘制输入也是碰撞输入；气垫船过水属于载具规则，不能把水域直接改为所有角色可通行。

## 6 分层与动画生产

### 6.1 分层交付

| 层 | 内容 | 遮挡原则 |
| --- | --- | --- |
| 地面层 | 地形底色、道路、湖水、沙带、田埂和大范围投影 | 进入地面缓存，不盖住前景人物 |
| 实体层 | 建筑、山体、树木、麦穗行、可遮挡摆件 | 使用脚底或底座锚点参与前后排序 |
| 角色与交互部件 | 猫身体、小手、武器、炮塔、控制器 | 保持独立锚点与现有操作机制 |
| 特效与界面 | 枪口、预警、光点、菜单和提示 | 按正式运行时规则叠加，不能烘焙进主体图 |

遮挡层不是简单的“所有建筑永远压住所有人物”。角色在物体前面应清楚显示，在后方按实际深度被遮住；关键区域使用现有透显机制。图集不能带不透明地板，否则会擦掉脚下场景并破坏排序。

### 6.2 正面猫猫序列帧

本项目只要求正面待机与正面移动主体，不为八方向重复生成身体序列。瞄准方向继续由小手和枪械表现。

生产链为：现有无枪主体参考 → 同源视频动作 → 筛选连续循环片段 → 抠像与统一裁切 → 固定脚底图集 → 姿态匹配 → 持枪运行时验收。

必须执行以下规则：

1. 待机和移动来自真实连续动作，保留源片、源时间与帧索引；不能复制一张图充当连续帧。
2. 摄像机固定，主体尺寸和脚底稳定；使用整段统一裁切及缩放，不能逐帧拉伸或重新贴底。
3. 呼吸、腿部、尾巴和眨眼柔和且有局部变化；整图上下漂移不能替代走路。
4. 起步和停止选择相近姿态衔接，暂停、驾驶和减少动态遵循现有时钟；不能停止就跳到不相关姿态。
5. 不把小手、枪、后坐、枪口火焰烘焙进身体视频。运行时继续使用正式的瞄准、握持与枪口坐标。
6. 改品种时检查全部帧，特别是耳尖、毛束、颈线、尾部和脚底，防止局部修形闪烁或超出帧格。

### 6.3 其他动作

怪物保留移动或飞行、受击、死亡；领主保留蓄力、释放和恢复。胶质怪物除整体挤压外，还需有边缘、波峰与表情的局部错相变化。履带运动与车体移动一致，停驻时不滑动；直升机主尾旋翼须连续转动。

浮游炮体、手持控制器、普通枪械及无人机分别交付和验收。可用局部程序动画完成的部件继续复用现有绘制器，不要求一律改成位图序列。

## 7 生成路线与提示词

### 7.1 先确定阶段，再选生产方式

| 阶段或需求 | 首选路线 | 输出 |
| --- | --- | --- |
| 动态效果开发，包括新增UI与场景交互 | imagegen 辅助参考，程序与 SVG 实现分层、动作、进度和操作 | 中文注释的源码、阶段性图片及其生成记录（如使用）、正式运行效果和验收证据 |
| 开发阶段延伸现有山体、湖岸、树木或摆件系列 | 扩展轮廓参数及现有 Canvas 绘制模块，可结合 imagegen 参考与 SVG | 形态数据、中文注释的绘制代码、正式预览与走位检查 |
| 动态效果确认后的美术精修与替换 | 以实机截图及已确认的 PNG 风格为参考，使用 imagegen 精修、裁切与编码 | 原图、透明 PNG 或 PNG 图集、生成记录、清单、锚点及替换前后验收 |
| 新玩法插画或确有需要的独立位图 | 开发阶段先验证实际容器、裁切与交互，可使用 imagegen 阶段性图片；精修阶段再交付 PNG | 本阶段图片与来源记录、容器及裁切说明；精修后补齐运行资源和验收 |
| 柔和主体动作 | 同源视频与连续抽帧 | 原片、源时间清单、处理后图集及动作预览 |
| 小手、枪械、后坐、履带、旋翼等机制相关部件 | 复用或扩展正式运行时动作 | 独立部件、锚点和连续帧验收案例 |

新任务按当前阶段延伸已经成立的生产方式；同源视频与机制相关部件的动作合同在两个阶段都有效。不要为了得到一张漂亮的大图，把原本可组合、可排序、可交互的场景合并为不可拆的背景。

### 7.2 通用风格段

将下段与任务单中的当前阶段、具体对象、尺寸和交付形式组合使用。开发阶段说明生成参考或阶段性图片的用途；精修阶段提供已确认的动态效果截图、PNG风格参考及部件边界。实际参考图应一并提供，不能只依赖文字。

> 延续《森林巡游》的二维森林绘本风格。统一三分之四俯视比例，圆润清楚的大轮廓，森林绿或随材质偏色的深色描边。柔和草木色与暖奶油色，有限平涂，明确的底色、背光面和左上受光面。地面投影朝右下，接触影贴紧落点。细节稀疏，正常手机游戏尺寸下能辨认主体。与提供的实机参考保持同系列的比例、光向和材质。

### 7.3 场景资产附加段

> 对象为【类别与形态】，识别特征为【至少两项结构差异】。保留【脚底或底座锚点】，按【地面、投影、主体、局部特效】拆分交付。周围使用【草坡、沙岸或田埂】自然衔接，花石与植物集中在边缘，留出【通行区域】。需要独立贴图时使用真实透明背景，不绘制棋盘格，不含界面文字。

### 7.4 猫猫视频附加段

> 严格沿用给定的原版猫猫身份、服装、脸型和比例。正面固定镜头，角色原地完成【柔和待机或原地走步】。脚底基准和主体尺寸稳定，动作连续、轻柔且可循环，耳朵和毛发稳定，保留细微呼吸、自然眨眼和真实交替腿部动作。身体不随方向转身；不生成小手操枪、枪械、枪口火焰或场景镜头运动。背景按现有抠像流程提供，最终运行资源交付透明图集。

### 7.5 排除项

> 不要写实摄影、另一套三维渲染风格、像素化重绘、纯黑厚描边、满屏高频纹理、强镜面、整片高饱和发光。不要对称复制岸线、规则圆环包湖、漂浮底座、额外肢体、主体比例跳变、动作复制帧、非需求方向、文字、水印或不透明地板。

排除项只约束本项目当前风格，不能替代正面的结构描述。首轮先选一件代表资源校准，通过正常尺寸及昼夜同屏检查后再批量生成同系列。

## 9 验收与修订

### 9.1 必须通过的检查

按任务单声明的阶段和本轮影响范围执行下表；不适用项说明原因。动态效果开发必须通过真实运行、动作与交互及同屏检查，记录本阶段已确认效果和待精修项，不因后续PNG尚未制作而判定本阶段失败，也不能据此宣称最终美术已完成。PNG替换阶段针对受影响部分复核下表，并以替换前的已确认效果为参照检查接口、进度、动作和交互。两阶段均不能只凭生成预览或自动测试通过验收。

| 检查维度 | 通过条件 | 留存证据 |
| --- | --- | --- |
| 系列一致性 | 正常游戏尺寸下，与原角色和场景的视角、描边、颜色及比例协调 | 与原资产并排图及实机截图 |
| 结构辨识 | 六类变体在低细节或剪影状态仍有区别，不仅依赖换色 | 同倍率变体对照图 |
| 体积与落地 | 亮面、暗面和根部清楚；主体与投影不漂移、不重复 | 白天局部截图 |
| 景观融合 | 主体、过渡地面和边缘生态连贯；核心活动区保持开放 | 整组景观图及实际走位 |
| 前后遮挡 | 角色从前、后、侧面经过合理；麦田按行遮挡；高山树冠不误裁 | 连续走位录制 |
| 水界与通路 | 视觉岸线与阻挡一致，普通角色不踏水，气垫船能过水；桥头与入口可达 | 正式运行时验证和相关测试 |
| 动作真实性 | 局部肢体连续变化，脚底稳定；起停、暂停与恢复没有跳姿态 | 多个连续帧和动作视频 |
| 操控部件 | 小手、枪口、后坐、炮塔与独立装备正确连接 | 多个瞄准方向的实战录制 |
| 昼夜及小屏 | 白天、夜晚同屏包含角色、怪物、载具、场景及UI，关键目标可读 | 手机和桌面各一组昼夜图 |
| 资源与性能 | 无缺失、帧越界、透明毛边、缓存泄漏和超出约定预算 | 资源检查与内存诊断记录 |

移动端至少核对当前项目常用的320和390像素宽度，桌面核对实际竖版战场布局；不能只放大单件资产审查。涉及交互资源时额外验证点击、拖动与界面遮挡。涉及循环地形时额外验证地图边缘镜像及地块接缝。

### 9.2 正式验收入口

验收案例写入 `visual-contract.json`，通过 `src/rendering/visual-review.js` 绑定实际绘制器。每个案例记录对应的 `designCriterion`，检查结果明确回答这个设计目标是否成立。

已有场景案例包括 `landscape-group-0` 至 `landscape-group-5` 及各自的 `-night`；猫猫案例为 `hero-breed-0` 至 `hero-breed-5`。新资源若需要新增案例，应复用实际运行路径，不为工作台另画一份更漂亮的示意图。

技术检查按变更范围选择：景观可复用 `tests/landscape-varieties.test.mjs` 和 `tests/landscape-varieties-browser.cjs`，动作复用相应猫猫、怪物、载具测试。自动测试证明规则和数据成立，人工复核负责比例、疏密、柔和程度与整体审美；两者不能互相替代。

### 9.3 退回与修订原则

出现比例或视角不一致、仅换色的重复变体、光向冲突、漂浮影子、岸线与碰撞不一致、堵住活动空间、假动作、锚点抖动、烘焙枪械或缺失资源时，退回修订，不进入批量生产。

修订优先修轮廓、空间和机制，再修材质与细节。已合格的猫动作、小手操枪、地图留白、昼夜和资源结构保持稳定；每轮只扩展有明确目标的部分。确认后的新样例更新到长期参考目录，并记录标准版本、修改原因及受影响的资产类别。

## 四境森林的植被与季节补充（2026-10-21）
