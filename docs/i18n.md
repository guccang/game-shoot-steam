# 中文语言表与后续翻译

当前默认语言为简体中文，2,544 条文案集中在 [`src/i18n/locales/zh-CN.json`](../src/i18n/locales/zh-CN.json)，并已提供完整的 [`en-US` 英文包](../src/i18n/locales/en-US.json)。覆盖首页、菜单、无障碍属性、HUD、Canvas 标签、装备与角色配置、剧情对白、提示和数值工作台，也包含 `Lv.`、`Boss`、`Debug`、分位数、秒数单位与资源缩写等英文显示文本。中文注释、稳定 ID、存档键、资源路径及玩法数值不属于翻译内容。

## 修改中文

在 `zh-CN.json` 搜索现有中文，只修改对应键右侧的字符串。保存并刷新页面即可生效，不需要修改或构建 JavaScript。键前缀表示首次使用模块，后缀是迁移时生成的稳定标识；修改译文时不要改键。相同文案共用一个键，修改会作用于所有引用。

例如 `config.heroes.10cb799373` 当前为 `栗子`。角色配置与剧情中同名说话人的独立姓名引用共用这条文案；完整句子中写出的姓名仍需随句子一起翻译。

剧情对白使用 `[人物 ID, 台词]`，例如 `player`、`snow`、`boatman`。发言位置与气泡通过 ID 查询人物，姓名只用于显示；译名相同也不会串用锚点。日志入口 `storyDialogueLines` 仍返回显示姓名与台词，存档继续保存章节、对白及分支 ID。

## 添加其他语言

1. 将整个 `zh-CN.json` 复制为目标语言的 JSON 文件，保留全部键，翻译字符串值。现有 `en-US.json` 已完成英文翻译，不要用中文覆盖。
2. 编辑 [`src/i18n/settings.json`](../src/i18n/settings.json)，登记文件并设置默认语言：

```json
{
  "defaultLocale": "en-US",
  "locales": {
    "zh-CN": "./locales/zh-CN.json",
    "en-US": "./locales/en-US.json"
  }
}
```

3. 刷新页面。语言包会先于玩法配置加载，角色、地图和装备名称不会保留旧语言缓存。存档仍按原来的稳定 ID 读取，不需要清档。
4. 如需保留默认中文并预览另一种语言，只登记语言后访问 `/?lang=en-US`。数值工作台也支持 `balance.html?lang=en-US`；后台模拟 Worker 沿用当前语言。

已交付中文和英文两份完整语言包，仓库默认配置仍为 `zh-CN`。英文预览访问 `/?lang=en-US`，工作台访问 `/balance.html?lang=en-US`；返回中文可使用 `?lang=zh-CN` 或移除参数。若要默认显示英文，只需将 `settings.json` 的 `defaultLocale` 改为 `en-US`，不修改程序代码。切换采用刷新页面方式，不新增游戏内的语言菜单。英文术语与验收记录见[英文语言包说明](i18n-en-US.md)。

## 翻译格式

- `{p0}`、`{p1}` 等是动态参数，可以在句子中调整顺序或重复使用，不能遗漏或改名。例如 `第 {p0} 波` 可以翻译为 `Wave {p0}`。
- `{companion}` 等命名占位符由剧情系统处理，同样必须保留。
- 保留需要的空格、换行和计量单位；长译文需要实际检查手机与桌面排版。
- 语言表只保存文字，不添加 HTML 标签、脚本或样式。界面结构留在原有 JS/HTML 中。
- 缺失键、空值、参数不匹配、未注册语言或文件加载失败都会明确报错，不静默混用中文。首页显示语言表中的启动失败提示，详细异常保留在控制台。选定语言包本身无法加载时，仅此失败提示读取中文基准表，游戏仍禁止启动。
- 运行时直接加载 JSON 模块，保持现有静态服务器部署方式；使用支持 ES 模块、顶层 await 和 JSON import attributes 的现代浏览器。Node 检查在 24.13.0 上验证。

## 新增文案的开发约定

在中文表中添加稳定键，同步补齐英文及其他已注册语言，再使用 `i18nText(key, { p0: value })`。配置、普通文本节点和 Canvas 都通过这个入口取文案。动态 HTML 使用 `i18nHtml` 转义译文，标签仍保留在 UI 模板中；传入的参数沿用现有受控 HTML 片段的约定，外部输入必须由调用方转义。

静态 HTML 的独立文本节点使用 `<!--i18n:键-->`，属性使用 `data-i18n-aria-label="键"`、`data-i18n-title="键"` 等，`title` 元素使用 `data-i18n-text="键"`。`localizeDocument` 在界面创建前填充，并且每个文档只执行一次，重复挂载不会覆盖运行中的动态 HUD。不要添加包装元素改变现有布局。
