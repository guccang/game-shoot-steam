# 晴叶营地第一章剧情与玩法执行方案

版本：1.0。设计日期：2026年10月22日。章节标识：`sunleaf-01`。建议展示名：**没有寄出的回信**。

本章让玩家扮演栗子，寻找失联的薄荷，发现巡护网络正在重复播放错误的求救信号，保护薄荷修复中继站，并击退被信号惊扰的铁牙野猪王。玩家通过两条路线和三套借用配置，体验走位、装备协同及任务完成后的世界变化。

这是设计基线。2026年10月22日已实现第一版，实际坐标、调参、验证证据与尚未完成的真人体验验收见[实施验收报告](story-reports/sunleaf-01.md)。下文保留原始调试起点供对照。主线首玩目标12–18分钟，熟悉后的通关目标8–12分钟；包含三套配置的完整试射与比较时，一次体验目标20–30分钟。此前20–30分钟的章节设想在这里拆为主线与可选体验，不以等待、重复刷怪或强制读台词补足时长。战斗参数是首轮调试起点，地标坐标是待碰撞验证的候选点，最终数值与落点须经下文验收确认。

## 1 交付范围与现有基础

第一版交付一条可完成主线、两条互斥路线、三套整套借用配置、一次三段守点、一场野猪王战、八个阶段检查点、一次性结算以及回营后的设施与人物变化。实现沿用原生JavaScript、Canvas 2D、原坐标和分层。

| 内容 | 当前已有能力 | 本章新增范围 |
| --- | --- | --- |
| 角色 | 栗子和薄荷的真实连续视频帧、六猫外观 | 栗子固定主角；薄荷作为静止交互人物，复用真实待机；雪团仅通过文字通讯出现 |
| 战斗 | 自动瞄准、实弹和激光、扑击预警、击退、独立车载武器 | 章节固定敌人编排、保护目标的攻击适配、章节专用参数快照 |
| 元素 | 水浸持续1.2秒；电弧对水浸目标伤害乘1.25；冰晶减速 | 组合教学和触发统计，不增加新元素反应 |
| 载具 | 松果战车、气垫船、坦克及其独立主炮、毁坏修复 | 三套借用装备、章节车体耐久覆盖值、安全区换装 |
| 世界 | 晴叶营地、营地建筑、道路、自然山湖、昼夜天气 | 任务交互物、经过验证的路线、章节地图标记和完工状态 |
| 存档 | 森林与秘境快照、领取事务、旧档校验 | 独立章节进度、阶段重试、一次性奖励账本 |

明确不包含：新地图、第三条水路、护送人物寻路、六猫组队、好感度、复杂对话树、永久技能树、新武器、全套任务编辑器。新角色技能和机械召唤流派留到后续章节，避免本章同时验证过多变量。

代码依据见[角色](../src/config/heroes.js)、[武器](../src/config/weapons.js)、[车型专属武器](../src/config/vehicle-armaments.js)、[命中与状态](../src/core/game.js)、[电弧](../src/combat/elemental.js)、[野猪王状态机](../src/combat/bosses.js)、[守护目标参考](../src/core/battle/guardian-defense.js)和[架构说明](architecture.md)。历史说明可能落后于源码，例如当前气垫船已经有20号双联潮汐炮，本章按代码配置执行。

## 2 剧情与角色职责

起因：薄荷接到“旧哨站有人需要帮助”的巡护信号后离开营地，未按约定回信。雪团发现同一句求救声重复出现，派栗子带着工坊的试用装备去找她。

中段：路边留下了薄荷的识别布条。找到她后，玩家得知现场没有求救者，中继站却在反复广播；异常声响正在把周围生物引向营地。薄荷已经找到线路问题，但独自无法一边修理一边防守。

高潮：恢复线路后，信号短暂增强，铁牙野猪王冲入空地。栗子保护维修区域，击退野猪王，再手动关闭错误广播。野猪王是受惊的森林领主，本章不确认它是幕后敌人。

收束：薄荷通过恢复的中继站向营地报平安。日志里显示，异常信号经过雾松密林转发。回营后补给站重新亮起通讯灯，薄荷留下第一封真正送达的回信。

| 角色 | 在本章的职责 | 表达重点 |
| --- | --- | --- |
| 栗子 | 玩家固定扮演的巡林员 | 主动确认现场、保护同伴；少说结论，多做行动 |
| 薄荷 | 失联的侦察员和修理者 | 有能力但需要配合；失联源于调查异常，不是无缘由等待营救 |
| 雪团 | 营地通讯与补给协调 | 温柔且明确，只在接任务、路线说明、回营时出现 |
| 铁牙野猪王 | 被广播刺激的领主 | 攻击依然危险；败退后广播仍需玩家关闭，明确问题来源 |

章节中固定使用栗子一级属性，不受永久选择的角色影响。进入页明确写“扮演栗子完成本章，结束后恢复原配置”。这样薄荷作为NPC出现时不会与玩家所选薄荷形成两个同名角色。章节不会解锁、购买或升级任何永久角色。

## 3 地点与路线

全部事件在四境森林的营地及南侧外围发生，复用既有地形。下面是设计拓扑，不代表已验证的道路或精确比例。

```text
营地工坊 → 倒下的路标 → 路线岔口
                          ├─ 林间主路 → 两次遭遇 → 补给箱 ─┐
                          └─ 林下近道 → 一次集中遭遇 ─────┤
                                                        ↓
                                       薄荷所在的旧哨点
                                                        ↓
                                         中继站三段守点
                                                        ↓
                                         野猪王战斗空地
                                                        ↓
                                       关闭广播 → 回营
```

### 3.1 选址合同

| 锚点 | 候选中心世界坐标 | 使用方式 |
| --- | --- | --- |
| CAMP | 900,700 | 使用已有营地入口，工坊交互指向已有建筑1010,580 |
| SIGN | 780,900 | 放置倒下路标和薄荷布条；避开已有帐篷、木堆 |
| ROAD1 / ROAD2 | 650,1040 / 620,1280 | 顺营地南向道路组织两次遭遇 |
| SHORT1 | 900,1160 | 林下近道的一次集中遭遇 |
| MINT | 800,1390 | 两路线共同汇合点，薄荷在开阔地等待 |
| RELAY | 700,1540 | 修复装置、停靠区和三方向入场点 |
| BOSS | 700,1780 | 领主战场；战斗边界目标半径280，不要求清空整个圆内植被 |

这些坐标不直接作为验收通过的出生点。开发任务D1必须使用当前正式地形和树干碰撞验证，并交付最终锚点表与路线截图：

1. 对每个候选中心按16单位网格、距离由近到远、最大160单位搜索；同距离按x、y排序，结果确定且写入章节配置，运行时不随机选址。
2. 交互点周围至少48单位可站立；修复目标周围至少96单位可通行；主路线连续净宽目标160单位，近道连续净宽目标112单位，同时不得低于最大借用车体碰撞直径加32单位。无论玩家选哪一套，都必须能走完两条路线。
3. BOSS场地必须有两条不同方向、各至少340单位的合法冲锋走廊，以及可横移离开实际预警的侧向空间。若现有水域、山体或树干使条件不成立，重新设计该锚点，不能靠删除碰撞或缩小玩家通过。
4. 验证角色、坦克、气垫船的完整路径；禁用跨世界边缘绕过路线。必要的地形调整单独进入美术任务单，不默认清除整片树林。
5. 选址失败时显式报告锚点与阻挡原因，禁止静默改用营地中心或把目标放入水中。所有地图入口、任务方向提示与碰撞使用同一最终坐标。

### 3.2 路线取舍

| 规则 | 林间主路 | 林下近道 |
| --- | --- | --- |
| 展示说明 | “路程较长，敌人分散，途中可补给” | “路程较短，敌人集中，没有中途补给” |
| 遭遇 | 两组，各8只普通芽团 | 一组：12只普通芽团和1只重卫 |
| 同屏上限 | 每组6只 | 8只 |
| 路程目标 | 经验证后约为近道的1.4–1.6倍 | 作为较短基线 |
| 路线收益 | 第二组结束后一次性恢复角色50生命、车体60耐久，上限封顶 | 少一次遭遇与较短路程，更适合清群配置 |
| 固定内容 | 薄荷布条和异常广播线索 | 同样的线索，不能因选择近道遗漏主线信息 |
| 汇合后 | 进入相同守点与领主战 | 进入相同守点与领主战 |

路线在岔口通过两个世界标记选择，点击显示上述短说明，再点击“从这里出发”提交。提交前可来回比较；提交后本章本次流程锁定，失败仍保留路线，重玩章节可选另一条。

锁定后只生成所选路线敌人、补给与目标。未选路线的地形可见，但绕过去不能激活内容；需要完成所选遭遇并抵达汇合点才推进。禁止用空气墙包住每条路，偏离路线时仅显示目标方向。

## 4 任务状态与推进条件

阶段ID是存档和事件键，中文名称用于界面。`Q10`至`Q80`对应八个阶段检查点；`Q00`是未进入章节的接取状态。任何完成判定由规则层执行，UI只能发起交互请求。

| 阶段 | 屏幕目标 | 触发与完成条件 | 战斗或交互 | 保存与下一步 |
| --- | --- | --- | --- | --- |
| Q00 接取 | 找到失联的薄荷 | 在营地通讯牌48单位内选择“开始第一章”；不在秘境、死亡或领主战中 | 打开交互面板即暂停森林，展示扮演角色、借用与检查点说明 | 冻结森林现场，建立章节会话，进入Q10 |
| Q10 借用装备 | 选择一套巡护装备 | 选定三套之一并点击出发；可先完成可选试射 | 试射用正式训练靶与正式枪械流程，不发资源 | 保存整套配置，进入Q20 |
| Q20 寻找痕迹 | 调查倒下的路标 | 到SIGN，清除6只芽团后在48单位内交互；读到布条和重复广播 | 单组教学遭遇，最多4只同屏 | 保存线索与当前供给状态，进入Q30 |
| Q30 选择路线 | 沿选定路线寻找薄荷 | 选择路线；清除本路线全部敌人并抵达MINT的96单位内 | 按路线表执行，路过目标不能跳过战斗 | 保存路线、已用补给与抵达状态，进入Q40 |
| Q40 找到薄荷 | 与薄荷确认情况 | 清场后在48单位内交互；对话读完或跳过均可完成 | 对话结束开启整备，可换配置；点击“开始修复” | 整备统一恢复角色、车体和供给至满；以最终选择建立Q50检查点 |
| Q50 修复中继站 | 保护中继站 0/3 | 三批敌人各自清除后修复一段；第三段完成且无存活敌人 | 目标300生命，三批守点；具体见第7节 | 一次保存完成旗标、幸存状态；进入Q60准备，不自动开Boss |
| Q60 击退领主 | 离开冲锋路线，寻找反击机会 | 准备区点击“迎战”；野猪王生命归零且援兵清除后完成 | 固定章节领主，不使用森林12杀资格或无尽波次倍率 | 保存领主完成旗标；进入Q70 |
| Q70 停止广播 | 关闭错误广播 | 返回RELAY，在48单位内交互2秒；无需长按，不受现实昼夜影响 | 成功后装置切换修复状态，薄荷报平安 | 保存关闭旗标，显示“返回营地”，进入Q80 |
| Q80 送达回信 | 向雪团报平安 | 选择返回后传送至章节营地交互点，点击通讯牌交付 | 短对话、回信与一次性奖励卡 | 原子写入完成、世界旗标、奖励和会话结束；恢复森林现场 |

每次阶段推进都检查：当前阶段匹配、章节ID匹配、事件对象仍有效、前置旗标成立、该完成事件尚未消费。反复点击、晚到的死亡事件和重复动画回调不能再次推进或发奖。

调查默认点击一次后播放2秒交互动作，走出48单位或受到攻击则取消，进度重置；进入菜单则暂停。战斗中只显示短目标与方向，不强制弹出长对话。关键对话每段最多三句，可逐句点击或整段跳过，已读内容进入章节日志。

主线时长预算按接取与选装2–3分钟、痕迹与路线2–3分钟、相见与整备1–2分钟、守点3–5分钟、领主及结束3–5分钟估算，移动和阅读计入各段。预算用于检查节奏，不能当作强制倒计时。路线未交战的移动部分预计很短，不把现有地图上的几百单位距离描述成几分钟探索。

## 6 三种战斗配置

| 驾驶速度倍率 | 正式松果战车1.00 | 正式气垫船1.12 | 正式坦克0.78 |
| 擅长情境 | 把敌人引成直线、稳定转移火力 | 密集目标、边移动边水电连锁 | 减速目标、用重炮压住关键方向 |
| 主要短板 | 多方向散开时难发挥贯穿 | 依赖水弹命中和水浸窗口，车体较脆 | 转移较慢，主炮装填时火力有空档 |

倍率和车体耐久用于建立初始测试基线，不表示三套已平衡。正式试射必须包含实际装填、命中率和移动，不用面板伤害除射击间隔宣布通过。

### 6.2 林线游击

选择卡文案：“拉成一线，边走边打。适合第一次巡护。”

角色激光沿用最多三目标及100%/50%/25%伤害衰减；机枪提供独立持续火力。玩家应在开放边缘绕行，让追兵在前后方向排队，然后利用贯穿。树干仍占据激光命中名额，不能让教学暗示激光无视树木。

20–30秒的可选试射摆出三目标直线与三目标散点，提示“换个位置，让更多目标落在一条线上”。检测到一次同发命中至少两个敌方训练靶时显示一次“贯穿命中”。未达成也可以离开试射，不把教程技巧做成主线硬门槛。

守点时从站点外沿引导攻击玩家的怪物，寻找与主进攻方向一致的射线。领主战主要利用松果战车较快的横向移动躲冲锋，持续射击收招中的领主。

### 6.3 潮电围控

选择卡文案：“水炮浸湿，电弧连锁。适合成群的敌人。”

气垫船20号主炮负责浸湿，角色10号电弧负责连锁，遵守角色枪与车炮独立瞄准、独立装填。现有规则是水浸持续1.2秒、电弧对水浸目标增加25%伤害，并非所有电弧命中都必定享受增伤。

可选试射以五只小范围分布的训练靶显示“先让水炮打中，再靠近保持电弧射程”。首次真实命中水浸目标时显示“水电协同”。只添加反馈和统计，不新增自动浸湿、全屏导电或保证先后顺序的隐藏规则。

这套配置允许下船，但下船后不能继续享有正在驾驶时的车炮协同；召回与上下车遵循正式规则。两条主线路径都在陆地可完成，不能因为气垫船能过水就使其他配置无法通关。借水域绕开某段敌人也不能跳过该段完成条件。

守点的优势是处理成群追兵，风险是过远追敌导致站点无人照顾。领主落单且水弹未命中时优势下降。若测试中协同很少出现，应先调整遭遇密度、指引与两枪射程配合，再评估是否需要独立的协同瞄准协议；首版不预置该协议。

### 6.4 霜炮守卫

选择卡文案：“冰晶拖慢，重炮开路。适合守住一个方向。”

冰晶对普通敌人沿用40%减速、持续2秒；领主沿用较弱减速上限，不能冻住冲锋。重炮沿用单发弹仓、真实装填、贯穿和强冲量。

可选试射让三只移动靶靠近玩家，显示“减速后等重炮开火，装填时横移”。首次出现冰晶减速目标被重炮命中，显示“控制接力”，这是事件检测，不额外附加伤害。

守点时提前占住重卫进攻方向，避免追着小怪跑。野猪王战必须提前横移；坦克耐久只提供容错，不应允许持续站在冲锋路径中硬吃技能获胜。

### 6.5 选择与更换

进入Q10、Q40整备、Q60开战前可以选择整套配置。失败后的重试准备也可换整套；战斗中只允许正式上下车和移动，不能打开永久工坊、换枪、换角色或切换借用配置。

Q40点击“开始修复”、Q60点击“迎战”时统一满角色生命、满车体耐久和供给，并清理上一阶段在途弹体。该整备发生在章节新阶段开始，不写永久状态。重试恢复本阶段起点，不保留上次失败的敌人伤害或额外资源。

配置选择时不立即补满；只有提交阶段准备才执行整备并写检查点。刷新准备页面仍停在准备阶段；刷新战斗则回到已提交的阶段起点。车体战中毁坏沿用30秒有效战斗时间修复，结束后仍需手动召唤。

Q10可选的“比较三套”提供线列、散点、接近目标三个场景，每个场景最长60秒，随时结束；分别试完三套约需6–9分钟，加上比较与选择形成20–30分钟体验。进入试射前后恢复Q10装备草稿，训练伤害、补能和用时不写入章节战斗检查点。各配置的20–30秒技巧提示属于该试射场景的开头，不再额外堆叠一轮必做教程。

## 7 遭遇与领主参数

本章敌人使用固定配置，不乘森林波次、出生区域等级、永久领主胜场或装备等级。它们保留正式移动、扑击、受击、死亡和地形碰撞。任务敌人不触发普通森林补刷。

| 单位 | 生命 | 单次攻击伤害 | 移速 | 备注 |
| --- | --- | --- | --- | --- |
| 教学芽团 | 90 | 8 | 45 | 只用于Q20，沿用普通前摇与扑击 |
| 普通芽团 | 120 | 10 | 52 | Q30和Q50主要单位 |
| 芽团重卫 | 320 | 16 | 42 | 复用高阶外观、质量和动作，只覆盖本表基础数值 |
| 铁牙野猪王 | 4800 | 冲锋30 | 42 | 复用正式领主技能与抗击退，具体见下文 |

敌人从可达且不与实体重叠的位置入场；入场点距玩家至少220单位，守点时距装置至少260单位。预警1.5秒；找不到合法点则延后尝试且不消耗名额。5秒仍无合法点须重选已验证备用入口并记录原因，不能在玩家脚下刷出。普通敌人全章同屏硬上限12，Boss援兵另受不超过4只的阶段限制。

### 7.1 三段守点

保护目标为中继站装置，最大生命300。薄荷位于旁边安全位置播放待机，首版不承担伤害、不寻路、不使用替代维修动作。修复表现由装置的三段进度与现有兼容工具效果承担，若新动作资源未制作，不以旋转整个人物伪造维修。

| 批次 | 敌人编成 | 主要入口 | 同屏上限 | 清场后的修复 |
| --- | --- | --- | --- | --- |
| 1 | 10只普通芽团 | 北侧单方向 | 6 | 清场后4秒，进度1/3 |
| 2 | 12只普通芽团、1只重卫 | 西侧和东侧交替 | 8 | 清场后4秒，进度2/3 |
| 3 | 14只普通芽团、2只重卫 | 北、东、西轮换 | 10 | 清场后4秒，进度3/3 |

同一批按1.2秒间隔补充，每次1只；达到上限时等待空位。下一批只在上一段修复完成后开始，并提前3秒标出方向。进攻方向与计数固定，刷新同一检查点不重新抽签。

出生序号每五只中的前四只以中继站为目标，第五只攻击玩家；重卫固定攻击中继站。保护目标复用现有攻击状态机，通过通用目标适配传入目标位置、半径与受伤入口，不能为了复用而伪装成一个真实的守护女神秘境。

站点攻击必须有正式前摇和单次伤害判定，不能用贴身每帧扣血代替。站点无玩家无敌帧时仍按每次攻击最多结算一次。任一时刻站点生命归零则失败；与最后击杀同帧时先处理伤害结果，再判定清场，站点死亡优先。

整个Q50只设一个战前检查点，失败或刷新重打三批。已完成前一阶段不回退；三段进度不分别发资源。首轮目标：熟悉玩家约2–4分钟完成守点，初次体验约3–5分钟，时间不够时优先改善任务节奏，不靠单纯加血拖长。

### 7.2 野猪王战

Q60先允许准备，再由玩家点击迎战。薄荷移出战斗区的叙事通过短淡出转场和新安全锚点表达，首版不做护送移动。中继站在此阶段不受伤，目标简化为击退野猪王。

沿用正式1秒锁向预警、1.1秒冲锋、1.5秒恢复以及340–620单位冲锋长度规则。预警与实际轨迹共用几何计算，遇河岸和边界实际截断。保留正常追击、前摇、释放、恢复，禁止额外强制无敌或按剧情锁血。

领主生命首次低于50%时，从已验证的两个外侧入口分批加入4只普通芽团，每次2只，间隔4秒。援兵从正式怪物流程生成，不再同时运行森林领主援兵管理器。新增敌人只制造转移火力的机会，不增加第二个Boss技能。

首个冲锋与首次恢复各显示一次短提示；后续同阶段重试不反复遮挡屏幕，但日志保留提示。野猪王归零后继续清除援兵，才进入Q70。战斗表现使用现有正式击败效果；台词称其“退走”，首版不新增奔逃动画。

目标领主战时长90–150秒，并在正常输出下至少展示两次完整预警、冲锋、恢复。若配置可直接秒杀，则调整章节伤害倍率或领主生命；若无输出空档仍过长，则降低生命。不能为了展示技能强制玩家停止造成伤害。

## 8 奖励与完成后的世界

全章只在Q80首次交付时发放：600金币、240木材、6机械零件、4能源晶体、1首领核心。两条路线、三套配置奖励相同；不按用时排名，不因倒下或换装扣减。

章节敌人、训练靶、领主、树木均不发永久掉落，不推进森林击杀、12杀资格、领主轮换、材料保底、武器熟练度或秘境纪录。章节领主奖励通过章节结算单发放，不调用森林领主战胜与材料首胜入口。这样重试、刷新和重玩不会成为重复获取核心的通道。

完成只写入以下永久内容：

- `sunleaf-01`完成及奖励领取标记；主线日志包含薄荷回信。
- 营地补给站通讯灯亮起；通讯牌可查看回信和重玩本章。
- 薄荷在营地固定位置出现并说一句通关后对白；若森林当前玩家也选择薄荷，则以通讯牌对白呈现，不绘制第二个同名薄荷。
- 地图保留旧哨点和中继站的完成标记；中继站使用修复后的外观。
- 展示“雾松密林还有一个转发点”的日志线索。第二章未实现前不出现可点击却无内容的出发入口。

补给站的首版世界变化不增加周期资源、免费永久装备或无限治疗。借用装备在离开章节时归还；结算卡可查看三套装备的正式获取来源，但不自动购买或变更装备追踪目标。

已通关后可从通讯牌重玩，使用独立重玩会话，选择任一路线和配置；不再次发永久奖励，不撤销世界完成状态。训练和重玩提供比较体验，不承担新的资源刷取功能。

## 9 失败与存档合同

### 9.1 会话隔离

首次进入前保存原森林成长引用、巡游检查点、地图与坐标、人物生命、弹夹与装填、全部车辆耐久及修复时间、召唤状态。当前页往返恢复森林现场对象；刷新后只能恢复可序列化检查点，按森林既有方式重建瞬态敌人与弹体，并暂停等待继续。

章节内禁止同时进入秘境、球赛、永久工坊交易、普通领主挑战或地图旅行，入口显示原因与“暂离章节”操作。暂离不额外弹出确认框，按钮旁明确“保留阶段，回来从本阶段起点继续”。森林后台不推进波次、补刷、装填和修复；环境仍遵循现有用户设置，不由剧情强制修改时段或天气。

章节会话接管正式Game和Renderer，不新建第二套战斗模拟。保存森林和章节使用原成长存档的一次写入事务；章节快照不能覆盖`progress.patrol`为章节战场，更不能污染`progress.realms.run`。

退出或通关后先恢复森林，再根据永久`worldFlags`应用通讯灯、薄荷和中继站外观，避免恢复旧场景覆盖新完成状态。返回后保持暂停并显示“继续巡游”，玩家操作后才恢复敌人和计时，不能在结算卡尚未关闭时受到原森林敌人的攻击。

### 9.2 数据字段

| 数据位置 | 必需字段 | 作用 |
| --- | --- | --- |
| `progress.story` | `version:1`、`chapters`、`worldFlags`、`run` | 旧档缺省为空；不变更既有装备编号 |
| `chapters['sunleaf-01']` | `completed`、`rewardClaimed`、`completedRoutes` | 完成与奖励身份稳定；重玩只能补充路线体验纪录 |
| `run` | `chapterId`、`definitionVersion`、`runId`、`replay`、`stageId`、`phase` | 校验会话及所处阶段 |
| `run` | `routeId`、`loadoutId`、`clues`、`readLines`、`flags` | 叙事与选择状态，使用白名单标识 |
| `run.checkpoint` | 人物生命、车体耐久、供给/装填/修复计时、已用补给、阶段起点、确定性种子 | 刷新与失败恢复统一来源 |
| `run.forestReturn` | 森林巡游检查点、地图与位置、装备供给及车辆快照 | 防止刷新丢失原森林返回状态 |
| `run.metrics` | 有效时间、分段失败次数、配置切换、协同事件计数 | 只用于本地验收，不参与奖励资格 |

`phase`只允许`prepare / active / dialogue / failed`。阶段战斗结束与下一检查点建立必须同一事务完成。若定义版本不兼容，保留永久完成与领取标记，归还原森林状态并明确提示重新开始该章；不能静默把坏存档当成已完成。

### 9.3 恢复矩阵

| 情况 | 恢复方式 |
| --- | --- |
| Q10未出发 | 恢复装备选择页，不默认替用户选择 |
| Q20或Q30中途倒下、刷新或暂离后返回 | 恢复本阶段起点；Q30已提交路线仍固定，同路线补给随检查点回滚但无永久收益 |
| Q40对话中刷新 | 恢复Q40，已读句子可跳过，不能越过整备提交 |
| Q50失败或刷新 | 恢复Q50战前准备，三批重打，中继站恢复300生命；可换整套配置后重试 |
| Q60战中失败或刷新 | 恢复Q60战前准备，领主与援兵重置，不重打Q50 |
| Q70或Q80刷新 | 从对应阶段继续，已击败领主不复活，交互完成旗标不重复执行 |
| 领取时保存失败 | 回滚钱包与完成事务，保留Q80可重试，不能显示领取成功 |
| 领取成功后重复点击或重新载入 | 根据奖励账本显示已领取，不再次入账 |
| 重玩过程中退出 | 保留重玩检查点或选择从头重玩，永久完成旗标始终保留 |

死亡不使用森林“回退三波”规则。章节重试不扣材料，角色与载具起点按该检查点恢复；Q50/Q60按整备规则满状态起步。损坏的坐标、装备ID、进度和负数计时必须被校验拒绝，不能携带不属于该配置的高级装备进入章节。

## 10 界面与美术执行要求

手机沿用竖版布局和原摇杆、自动瞄准、载具按钮。常驻区域只显示一行当前目标、必要计数和可收起的方向提示；不叠加任务清单、剧情对白和装备属性三块大面板。

- 任务日志从既有功能菜单进入，查看时暂停；列出当前目标、已读剧情和控制说明。
- 交互按钮仅在距离满足时出现，点击命中区域至少44 CSS像素；触摸滑动不得误触，桌面支持E键，按钮存在时提供键盘焦点。
- 台词在安全阶段使用可跳过对话卡；战斗通讯最多两行、同一时间一条，不遮盖预警、血量和摇杆。
- 三套配置卡首先展示打法、武器与车体，其次展示详细数值；整套选择和试射入口在320像素宽度下仍可操作。
- 路线选择不依赖颜色区分，配合路线名称、图标和文字说明；完成状态也保留文字与形状反馈。

需要制作或组合的内容：倒下与修好的路标、中继站损坏/修复两态、补给箱未用/已用两态、营地通讯灯、任务地图标记。优先组合现有木材、设备和工坊视觉；没有必要新增剧情插画或影片。

资产实施前完整阅读[美术资源生成标准](art-generation-standard.md)，复制[美术任务单](art-generation-brief.md)为`docs/art-tasks/sunleaf-chapter-one.md`，先填目标、参考、尺寸、锚点、分层、结构差异和保留项，再制作。任务单不能在设计阶段伪填“验收通过”。角色身体继续用真实连续帧，小手与枪独立；车轮、履带与车炮保持正式动作。

实现时在正式绘制器和visual-contract中登记以下`designCriterion`：`sunleaf-objective-readable`、`sunleaf-route-readable`、`sunleaf-relay-state`、`sunleaf-loadout-identity`、`sunleaf-boss-warning`、`sunleaf-world-return`。每项必须关联本章具体目标、昼夜与桌面/手机截图、正式绘制入口和通过/退回结果；缺资源明确失败。

## 11 工程拆分与依赖

## 12 验收与调参顺序

### 12.1 必须通过的规则测试

1. 新档、已有中期装备档、已通关档都能进入合法章节状态；永久属性不改变章节结果。
2. 三套配置乘数各应用一次，主炮编号与车体对应；水电25%增幅只在真实水浸期间生效，领主不受到普通怪同等强减速。
3. 两条路线各自完整走通；锁定、补给消耗、重试、绕路和跨边界都不能跳过完成条件。
4. 守点站点归零、玩家归零、最后击杀同帧等竞争事件结果确定；没有漏怪、超额出生或双重结算。
5. Boss阶段只运行章节援兵编排，野猪王按正式预警碰撞；零生命后的残留事件不再次推进。
6. Q10至Q80分别覆盖刷新；死亡、暂离、返回和清档覆盖；保存失败回滚、双击领取、重复重玩不重复奖励。
7. 章节外原装备、角色、车辆、森林波次、12杀资格、材料保底与秘境纪录保持；唯有明确的首次奖励与世界旗标发生变化。
8. 暂停、切后台、减少动态模式不加速交互/修复/装填；缺失美术资源或地标校验失败明确阻止开始并说明原因。

规则验收使用纯逻辑测试；端到端使用真实点击、移动与正式绘制器。运行项目`npm test`与`npm run check`作为集成检查，不以自动测试替代实际试玩。

### 12.2 正式试射与三套配置比较

每套在同一固定种子下测试：单个领主耐久靶、六只线列靶、六只散点靶、相同守点和Boss场景。每个样本至少60秒或直至目标清除，包含装填与车辆受损，不通过重置弹夹提高输出。

先调配置倍率，再调敌人数量和生命，最后调进攻间隔；每轮记录参数版本。需要验证的目标如下：

| 指标 | 首轮目标 | 若不满足如何处理 |
| --- | --- | --- |
| 三套同条件单体持续输出 | 最高/最低不超过1.25 | 优先调整该通道章节伤害倍率，不修改永久武器 |
| 三套关卡表现 | 没有一套同时在清群、守点损失和Boss用时上全面领先 | 调整遭遇结构或配置代价，不单靠伤害拉齐 |
| 潮电协同 | 固定守点样本中至少20%的有效电弧目标命中处于水浸状态 | 先查真实瞄准、射程与水弹命中，再改善指引/布局；该比例不是命中强制规则 |
| 霜炮控场 | 在相同进攻脚本下出现可观察的接近延迟及装填空档 | 查减速、目标路线与炮塔时钟；不能用额外隐藏伤害伪造优势 |
| 林线贯穿 | 人工拉线后多目标同发命中比例明显高于散点站位 | 查树干遮挡、引怪路线与提示可读性 |
| Boss | 正常90–150秒，至少两次完整技能循环 | 调血量和章节倍率，保留可提前击败的规则 |
| 站桩容错 | 无移动脚本不能稳定通过Boss，正常横移可显著降低受伤 | 查冲锋轨迹、耐久和伤害；禁止不可躲技能补难度 |

表中“有效电弧目标命中”包括连锁命中，以命中事件记录分母，不用发射次数代替；玩家手动操作样本另列，不混入固定脚本结果。

### 12.3 实际体验与画面

验收矩阵至少包含三配置×两路线的六次完整流程；其中至少覆盖手机触摸与桌面键鼠两种真实操作。每套还需在白天、夜晚各查看守点与Boss同屏，完成320×568、390×844、1440×1000下的关键界面检查。

真人可用性先安排至少5名未读方案的体验者作为形成性样本，不据此宣称统计显著。记录实际有效游玩时间和失败阶段，检查：

- 至少4人能在接取后说出“寻找薄荷”的目的，且无需旁人提示找到下一目标。
- 至少4人能描述所选配置的一项优势和一项代价，区分角色枪与车炮。
- 六条人工完整流程都能通关；不得有配置、路线或手机布局造成的必死/卡关。
- 主线首玩时长目标12–18分钟；完整试射与配置比较另计，整体体验目标20–30分钟。若明显短于目标但节奏完整，保留短流程并调整时长预期，不添加空跑和重复战。
- 结束后至少4人能回忆薄荷、重复广播和营地通讯恢复中的两项。

视觉检查必须核对正式角色连续动作、手枪分离、车轮/履带、水炮后坐、昼夜目标辨认、树木遮挡与实际碰撞一致、目标在镜头内可读，以及任务物是否遮住主路。性能以同设备、同敌人数的现有场景为基线，持续观察5分钟。新增任务图集解码与缓存预算合计不超过8 MiB，复用角色图集不重复解码；新增对象的更新与绘制使帧时间P95增幅不超过10%，暂停恢复后无持续增长的实体或缓存。达不到预算时先缩减装置细节和缓存，再复测，不能仅凭低敌人数宣布达标。

验收报告分别列“规则测试”“固定脚本战斗”“浏览器交互”“真人体验”“视觉与性能”；每项标明通过、退回或待验。仅规则测试通过时，第一章仍不满足最终交付条件。
