# 营地布局更新后移动卡顿

## 原因
以前镜头插值修复只处理位置连续性。后续布局功能引入两条新的重算路径：Renderer.syncCampLayout在任意锚点版本变化时清空全部森林地块；campRoadNetwork按存档对象WeakMap缓存，事务保存克隆存档后丢失缓存，装饰列表变化也触发整套路网重建。

复现中同步地块重建耗时约33–123ms；道路重算带来的单帧绘制峰值约240–306ms。两者都发生在主线程，呈现为建筑随镜头跳动，不能靠增加插值消除。

## 修复
地面只标记旧/新底座周边的缓存块。保留完整旧纹理，后台完成昼夜纹理后原子替换并释放旧像素；取消、换图、换季和销毁清理脏标记。容量仍沿用原预算，仅有当前工作块暂存。
道路缓存以建筑位置、门位、地契和农田占地为键，最多8种布局。正式道路复用保存校验时ignoreDecor的结果；装饰摆放继续避让道路，库存、作物生长、存档克隆不再触发寻路。真正改变布局或移动农田仍失效。

## 防回归与证据
新增camp-layout-ground-retention.test.mjs、camp-road-cache.test.mjs，检查局部刷新、旧纹理保留/释放、负坐标周期地图、连续更新、存档克隆、装饰变化与真实几何失效。既有道路宽度、最近分叉、布局、四向预热和缓存保留用例通过。

浏览器脚本tests/camp-movement-cache-stutter-browser.cjs使用正式绘制与固定步长表现插值，在营地视野内往返，执行移动建筑、更新装饰、再次移动建筑；复用保存阶段道路校验结果后，三段运行均无额外道路重算、无布局同步缺块。每段约151帧，绘制p95为4.4–5.3ms，峰值12.6–15ms。数值为本机该场景的绘制耗时，不代表所有手机和全部玩法的FPS承诺。

正式昼夜截图、录制与报告：output/playwright/camp-movement-cache-stutter/{day.png,night.png,video/,report.json}。已检查两家商店及花坛位置、遮挡、道路与夜间窗灯正常，无浏览器错误。此次不修改美术图案、动作及UI，只调整缓存生命周期。
