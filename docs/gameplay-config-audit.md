# 硬编码数值审计

> 以下是通用数字扫描，不是内容数值的待办数量。按用户确认的怪物、战车、任务与成长口径，参见 [内容表与剩余扩展限制](content-balance-tables.md)。后坐力、镜头、动作和导航采样不属于该内容范围。

## 扫描口径

`scripts/gameplay-audit.mjs` 用 Acorn 解析 `src/core`、`combat`、`progression`、`physics`、`world`、`config`、`ui`、`balance`、`app`、`platform`。记录每个数字字面量的文件、行、列、值及原行上下文，同时收集 `GAMEPLAY_VALUES.组.字段` 的引用位置。不会将注释、字符串里的数字、图片或视频当成参数。

扫描分类是审查辅助，不能自动认定所有数字都是玩法参数：`0/1` 也可能是概率，短间隔也可能是可调规则，配置函数中的数字也可能是数学公式。报告保留全部记录供人工复核，不把这些类别直接删除。纯绘制层、样式与资源帧数据不属于本次玩法扫描范围。

## 已完成配置化

新增键值覆盖暴击、受击保护、脱战回血、树木恢复、装备等级及部件成长、怪物品质与奖励、怪潮增长、秘境配额、领主技能、伙伴供给、消防任务、足球、生活交互和物理冲量。成组攻击、弹道和阶段数据独立成表。既有 59 个配置源纳入统一只读目录；清单由正式数据生成，详见 [配置清单](gameplay-config-inventory.md)。

统一了容易产生漂移的引用：瞄准预览与实际命中、祝福说明与伤害公式、成长上限与交易/读档、熟练度上限与解锁阈值、消防树组与恢复条件、载具扩容与恢复弹量、生活时段与日历/季节圆环。删除了会被经济结算无条件覆盖的领主旧中间奖励赋值。

## 尚未承诺可任意修改的数值

以下仍保留在现有代码或专用配置中，不能把本次结果称为“全仓库数字清零”。

| 范围 | 例子与位置 | 处理与原因 |
| --- | --- | --- |
| AI 移动与导航调优 | `combat/funnel-movement.js` 的泊位评分权重；`drone-movement.js` 的航道坐标；`summons/ground-motion.js` 的搜索步长 | 速度、加速度、交战距离比例、停靠阈值和射后变位已迁入统一表；剩余评分、航道和采样常量尚未全部迁出，需要区分导航算法与动作表现 |
| 地形与碰撞形状 | `world/paths.js`、`world/jiuzhaigou.js`、`physics/terrain-navigation.js` | 固定地图和算法采样参数仍在原定义；修改需要联动地图、通行和美术验收，不能当成独立平衡数值 |
| 运行保护及数值算法 | 迭代预算、浮点 epsilon、空间网格步长、向量归一化、积分中的二分之一 | 保留在实现；审计输出位置，不提供通用平衡编辑权限 |
| 固定身份与历史迁移 | 武器索引、存档版本、`progression/boss-health-migration.js` 中旧公式 | 属于稳定协议或历史解码依据，不能随当前平衡配置一起变化 |
| 纯表现 | 粒子数量、闪白时长、后坐幅度、UI 像素与动画曲线 | 不在本次平衡迁移中调整；若后续做表现工具，应建立独立美术配置合同 |
| 既有配置内派生公式 | 经济方案从原表复制后按系数生成、预览挂点计算 | 目录能查看导出结果；源文件仍包含公式，不能把派生值当作独立可回写字段 |

因此当前交付是可运行的主要玩法参数化、统一查看入口与完整扫描工具；AI 运动等剩余参数及全部旧表 schema 仍是进一步全面配置化的明确工作项，不能仅凭 `config:check` 通过宣称它们已完成。
