# 未击败领主时暂停清缴与补给验证

日期：2026-11-02。开发基线：main `d32a82f`。

## 原因与修复

暂停清缴的事务仍以 `game.boss` 存在为拒绝条件，与既有的距离脱战和安全区规则不一致。即使回到营地，也必须先击败领主才能暂停。恢复入口同样拒绝未完成领主；原接取流程还会重新选择场地。

本次调整：

- 活跃交战中仍需先撤退；远离领主脱战或回营后可以暂停。
- 暂停保存当前领主血量、位置、波次和脱战状态，保存失败不改战场。
- 暂停后终止领主攻击、危险区和所属援兵，不发击杀奖励，不因再次靠近自动开战；流弹和范围伤害也不能结算保留中的领主。
- 告示牌显示“继续本轮清缴”，继续原场地与原领主，不重抽地点、不重发奖励。进入原战区后按既有距离规则重新接战。
- 复用既有商店安全交互、NPC 对话及购买事务，验证暂停后可进入弹药铺购买所有弹药类型。
- 未增加存档迁移、图片或布局体系，使用现有字段和界面。

## 实际页面验证

`tests/clearing-boss-pause-browser.cjs` 使用 4175 端口和隔离浏览器存档，真实点击告示牌、暂停、售货员、购买和继续按钮。仅准备任务前置条件与测试位置，不替换游戏更新、暂停、购买或恢复逻辑。

结果：

1. Boss 血量为 321 时暂停，立即刷新仍保留血量、暂停状态和原战区。
2. 通过售货员对话进入商店；猫猫购入通用子弹 300 发；载具购入通用子弹 300 发、标准炮弹 50 发、重型炮弹 30 发、潮汐弹罐 200 发。
3. 金币从 1000 减至 640，与五笔商品价格一致，Boss 血量始终为 321。
4. 回告示牌点击“继续本轮清缴”，回到原战区重新接战，未重置血量。
5. 浏览器异常为零；320×568、390×844 昼夜界面已检查，继续按钮可见且触控尺寸不小于 44 像素。
