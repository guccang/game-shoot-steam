## 如何调参

页面顶部已内嵌六步使用指南与常见瓶颈排查，支持折叠和页内跳转。全部经济参数及路线假设旁均有用途说明，可点击“调整影响”查看调高、调低及不生效的条件；目标路线通过中文类别和装备名称直接选择。结果区可展开统计口径，导出区说明配置、报告和实玩记录的区别，无需对照本文操作。

1. 选择原版或推荐基线，编辑掉落、角色武器／车体购买配方、升级费用、成长倍率与挑战阶级；导出使用版本2 JSON，导入版本1会显式迁移为“不限制费用上限”的历史候选，保持原价格。缺字段、非法数值、错位目录会明确报错。
2. 选择混合／森林／偏某一秘境路线，设置效率、失败率、移动占比、养成预算和升级优先级。初始进度只复制；目标装备点击“添加装备”，选择中文类别和名称，用“上移／下移／删除”编辑购买清单，最多30件。清单从上到下购买，前项不满足条件会等待，已拥有的跳过；清空后需添加至少一件才能运行。导出报告继续保留原有稳定编号格式，无需手填英文或编号。
3. 运行 100 个固定种子，比较 P10/P50/P90、未完成比例、资源曲线、来源每分钟收益、事件时间轴与最长空档、后期全部种子的最大空档及超12分钟组数。后期从180分钟算到达标或模拟结束，包含跨段间隔、失败和未完成尾段。保留结果后修改参数可并排对照；长任务可取消。
4. 用正式试射比较同一武器的相邻等级。单体、怪群、领主耐久靶都走真实装填、蓄能、范围伤害与召唤链；不把面板伤害除间隔当作持续输出。
5. 导出配置与 JSON/CSV 报告。发布候选时，把验证过的数值写入仓库推荐配置，重新跑下列验证并提交；网页编辑不会悄悄改变正式游戏。

```powershell
npm run balance:simulate
npm run balance:simulate -- --config candidate.json --scenario route.json --out output/balance/candidate.json
npm run balance:simulate -- --route forest --efficiency 0.65
npm run balance:simulate -- --original
npm run balance:validate
npm test
npm run check
```

情景 `priority` 必须包含 `weapons heroes turret vehicle` 四类且不重复。模型按各类目标达成比例排序，比例相近时按优先级选择，避免第一类吞掉预算。`strategy: save` 的升级预算为累计收入的25%，其他策略使用可调 `upgradeShare`（默认40%）；交易仍逐笔真实扣费。

`workshopMinutes` 默认5，前30分钟最多2；它表示玩家消费习惯，**正式游戏没有新增升级冷却**。`expeditionMinutes` 默认6：同一趟秘境连续打完关卡，在开下一关前估计耗时，超出预算则主动返回，额外计15秒路程；退出/失败后下一次从第1关开始，只在返回森林后使用永久工坊。长途冲层可调高预算。活动权重按实际耗时欠账调度，单关、失败、休整及往返共用时间。

五阶以后模型允许继续强化当前主力到20级，而不是达到15/12/10/12就停止消费。完整路线最低目标仍为武器15、角色12、车体10、所选炮塔12；`completionLevels`记录达标瞬间等级，`levels`为整个模拟结束的等级，二者不能混用。

旧模型在秘境每关之间可直接永久升级、切换玩法后仍保留局内关卡，本轮一并修正。历史报告只作记录；价格作用必须看新版模型同条件下的 `previous-standard` / `previous-low` 对照。

## 战斗与实际运行证据

正式 30 秒靶场对照包含 8 种代表武器的四个关键等级（4→5、9→10、14→15、19→20），每组包含单体、怪群和 3000 耐久靶。手枪 4→5 的耐久靶有效输出为 88.33→107.20，约 +21.4%；前者 30 秒内未击杀，后者 27.77 秒首杀。角色生命 192→230、基础车体耐久 580→696。有效输出计算实际扣血，不计算溢出伤害；普通枪的平均开火数包含未命中，自动／召唤装备的开火事件不等同于手持枪数。

耐久靶没有领主 AI、追击和躲避行为。长周期模型以可调击杀吞吐、成长系数、敌人耐久和失败率估算时间，**尚未按每种武器的真实通关样本拟合吞吐**。靶场样本证明正式战斗成长链生效，不能证明所有装备的实际清关时间已校准。

`real-raf-30min.json` 来自真实 RAF 运行 1800.36 秒，其中记录有效时间 1795.26 秒，自动操作死亡 13 次；使用真实方向键事件和交易接口，没有加速游戏时钟或增加无敌。开局约 1 秒首次升级，结束时领主累计 11 次、原手枪 12 级、角色 12 级，并购买散弹枪追赶到 5 级。脚本前段曾停留角落，中段改为接近敌人；路径会附带砍树，**不是零伐木真人样本**。该记录保留校准时配置（当时费用指数 1.5），不能冒充最终 1.4 配置的完整人工验收。正式零伐木可持续性由模型与交易守恒检查验证。

中后期隔离存档验证了实际工坊施工、30% 追赶价、5 级关键收益、塔 40 层解锁浮游炮、购买持久化与经济记录下载；手机 320/390 和桌面 1440 的昼夜正式场景及工坊均检查。截图和对应设计标准见 [美术任务单](art-tasks/economy-workbench.md)。是否愿意持续使用新装备仍需目标玩家试玩反馈，本轮没有编造这项主观结论。

## 共享规则、存档和账本

`src/config/economy.js` 提供不可变基线与纯规则；正式交易、工坊报价、模拟调用相同规则。工作台通过不可枚举的候选配置绑定隔离进度，JSON 存档不携带调参数据。运行中候选编辑只影响下次模拟。

保留原所有权、等级、部件、熟练度、钱包和领主快照，不撤销装备、不追扣费用。挑战资格从原 `bosses` 与三种秘境 `records.best` 推导；无历史字段的旧档默认 0，已有装备照常装备升级。领主首胜材料记录缺失时按已有森林胜场推导已见领主，防止迁移重复领取。难度下限只在创建下一次领主快照时应用。

本地账本累计时间、来源、支出与挑战事件；仅前台有效状态计时，选牌、布防、休整纳入成本，暂停、后台和已结束的比赛不计时。事件最多 600 条，同分钟连续同来源收入合并；摘要保留累计数值，导出说明淘汰数量。满仓只记录实际收到的资源。账本不上传，也不作为恢复钱包的依据。

工程验证覆盖奖励幂等、原子扣费、保底恢复、首奖、同类追赶、永久／局内钱包、旧档、候选隔离、配置错误、固定种子、资源守恒、真实伤害及工坊交互。合并其他同期功能后 `npm test` 与 `npm run check` 均需再次通过。
