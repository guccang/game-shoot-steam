# 伐木卡顿优化验收（2026-11-10）

## 测量方式

使用正式 Game.hit、CombatFX、木材事务和空间索引，浏览器为 Edge 无头模式，390×844 手机视口，4 倍 CPU 降速；森林 42,845 棵，连续测量 24 次单棵死亡。每轮清空背包以排除满载跳过。使用隔离浏览器 localStorage，不访问用户存档。

计时脚本默认 http://localhost:4175。本次该端口已有服务，隔离 worktree 使用 TEST_URL=http://localhost:4176。PLAYWRIGHT_MODULE 可指定本机 Playwright 模块路径。

| 环节 | 修改前平均毫秒 | 修改后平均毫秒 |
| --- | ---: | ---: |
| 命中结算（含下列子项） | 9.575 | 5.983 |
| 事务复制（子项） | 5.017 | 1.646 |
| JSON 序列化（子项） | 1.083 | 1.004 |
| 保存调用（含序列化，子项） | 1.629 | 1.783 |
| 命中特效（子项） | 0.208 | 0.217 |
| 死亡清理 | 10.975 | 0.358 |
| 清理后空间索引查询/重建 | 58.333 | 0.000（计时精度内） |
| 命中＋清理＋索引 | 78.883 | 6.342 |

结论：受测路径平均减少约 92%。主要改善来自不再重建全森林索引、不再扫描全部活树清理、减少事务复制。不能将子项再次相加；保存调用单次耗时没有下降，增量方案的价值是减少主档写入字节并保留同步持久化语义。上述数据是受控路径耗时，不是整机帧率或真机承诺。

## 实现和一致性

- 正式命中、领主毁树和树桩入口登记死亡对象；帧末从原数组和共享分桶移除，存活顺序不变。无死亡不扫描森林。
- 蜘蛛与领主复用共享索引，砍树不抛弃蜘蛛有效路线；补种和换场仍重建索引。同帧补种后死亡也不会漏掉新障碍。
- 木材事务只复制其会修改的分支，账本旧事件及图鉴等只读共享；保存失败不污染旧进度。
- 连续伐木向一个累计增量记录同步写入，主档带唯一基线代号。刷新时只应用匹配的增量；普通保存、退出和检查点提交完整主档，新代号令旧增量失效。
- 没有延迟到账或仅存在内存中的待保存奖励。每笔木材保存成功后才到账、播放飞行动画；失败保留原有拒绝入账行为。两秒检查点、离页及其他普通操作仍可写完整主档。
- 奖励事件的后续账本保存也走累计增量，不再因每棵树重写主档。没有修改动画、美术资源、伤害或负重规则。

## 验证

针对性单元检查覆盖 wood-pickup、wood-journal、spatial-grid、quest-route-performance、spider-follow-stability、earth-landforms、reset-progress、map-save-reset，以及 boss-terrain 的跨边界扫掠/波环用例。验证：连续奖励、配额失败和重试、刷新恢复、清档、花费后的旧记录隔离、HTTP 无 UUID 环境、碰撞和绘制顺序、同帧补种、领主死亡队列、树桩再生、导航缓存。

真实页面使用 390×844 手机视口，在森林昼夜各连续摧毁 8 棵树，边移动边产生正式碎屑和木材飞行：64 份木材到账，重新创建存储适配器读取也为 64。每组 16 次小增量写入，1 次周期检查点主档写入。继续用正式自动瞄准、手枪弹丸和碰撞边走边射击，库存 64→80，存档恢复为 80，角色移动约 217 世界单位。无 pageerror。昼夜截图已检查角色、树木、碎屑与 HUD 同屏。实际页面采样最大帧间隔昼间 66.7ms、夜间 50ms（包括整页逻辑与截图等测试工作），仍可能有其他系统帧尖峰，不把局部优化宣称为全场景恒定帧率。

旧 boss-terrain 综合文件共 9 项，6 项在本 worktree 和未修改 main 均失败，涉及旧领主阶段、技能与旧奖励断言；本次未改写这些旧断言。跨边界扫掠用例通过，并补充独立的共享索引/死亡队列验证。本次未运行全量测试。
