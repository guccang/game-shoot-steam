## 验证与限制

- 针对8个直接关联测试文件运行44项检查，覆盖真实击杀清波、暂停、死亡回退、补刷等待、分组领主、计数、倒计时及存档。首轮40项通过；4项清档断言在未修改的master上也失败，原因是正式清档已切换入职档、断言仍使用旧基础档。仅将预期更新为正式`freshRangerProgress()`后，这4项重新通过，生产清档逻辑不变。没有运行全量`npm test`或国际化检查。
- 旧档第1波已杀8只时只补4只；已杀20或36只的旧档按新配额进入休整，累计击杀和已有金币、木材保留，不重复发奖励。原有领主快照与等待节点测试通过。
- Node正式战斗采样使用5个固定种子（11、37、73、101、233），390×844视口、初始1级手枪、站定自动射击、无载具，保留出生、装填、伤害与地形；使用固定1/30秒步长。旧版5个样本均在清完36只前倒下；新版5个样本均清完12只，用时22.83–24.07秒，中位数23.50秒。此为脚本采样，不代表真人游玩时长。
- `tests/opening-wave-browser.cjs`在隔离端口4248运行真实页面与RAF，首波显示`0 / 12`，实际自动射击清完12只并进入第2波，详情同步为18只；不向这段实跑注入击杀、无敌或升级。首轮实测游戏有效时间约19.60秒清波、22.60秒进入第二波。
- 浏览器随后使用单独视觉夹具验证1280/390/320宽度与昼夜，详情文字换行、边界、暂停与Escape关闭均通过，无页面异常。视觉夹具中的载具与生存保护不计入上述战斗数据。

本轮为数值修改，未新增或修改美术资源、绘制函数、UI结构或样式；同屏复核沿用`wave-compact-help`设计标准和正式`createWaveHelp`、场景绘制器。关键截图：[首波12只](art-reference/opening-wave-first.png)、[桌面白天](art-reference/opening-wave-scene-1280-day.png)、[手机夜晚](art-reference/opening-wave-scene-390-night.png)、[320宽详情](art-reference/opening-wave-detail-320-night.png)。

每只怪物的奖励未增加，因此提前到达同一波次时累计刷怪收入也会减少；本轮验证的是开局清波反馈，没有重做完整8–12小时经济路线验收。此前未获合并授权的JSON配置分支不包含在本次改动中。
