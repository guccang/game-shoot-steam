# 渲染提交与 HUD 重复更新优化任务单

依据：[美术标准](../art-generation-standard.md)、[项目规则](../../AGENTS.md)。

## 1 目标与范围

名称/标识：渲染提交与 HUD，`render-submit-hud`。类别：已有运行时 UI 的性能改进。
当前阶段：动态效果开发与交互复核；本轮不生成或替换 PNG。目标：现有按钮和卡片保持外观、锚点、文字与交互，只减少不必要的 DOM 写入和重复布局。
动态目标：目标/资源/暂停变化立即反映；移动时继续跟随原建筑或角色投影，不能把实时位置缓存成静态截图。
数量和变体：附近交互控件、任务/领主/装备 HUD；不新增视觉变体。
保留项：中文字体、字号、配色、按钮尺寸、猫/怪物/载具动作、独立操枪、昼夜与移动。
制作路线：沿用原程序与 CSS，仅调整更新顺序和变化判断；参考 src/ui/nearby-interaction.js 与 src/ui/task-combat-layout.js。
确认目标：手机短屏和长屏同屏可读、触控至少44px、工坊目标立即切换。
后续精修：本任务不改变美术资产，没有新增 PNG 精修项。
使用场景：营地工坊、附近设施交互、任务与秘境 HUD。

## 2 造型与空间

主体剪影、变体差异、主次关系、地面衔接、邻接组合与光向明暗：沿用当前正式画面，不新增形体或调整图层。
活动空间：地图和碰撞数据无改动，工坊按钮仍绑定屋顶，普通按钮仍绑定原角色附近投影。

## 3 技术交付

逻辑尺寸与倍率：沿用实际 DOM/CSS 尺寸，读取真实高度；不新增位图缩放或图集。
锚点：工坊最近世界镜像屋顶上方，避开资源栏/任务栏；其他交互保持原位置规则。
分层与透明：现有 DOM 覆盖层，不向 Canvas 烘焙文字或按钮。
碰撞：不适用，纯界面更新；没有修改桥头、水界、实体边界。
昼夜：沿用原场景环境光，按钮材质不变。
文件：src/ui/nearby-interaction.js、src/ui/task-combat-layout.js；诊断见 src/platform/canvas-command-sampler.js。
预算：不增加运行图集或像素缓存；采样报告最多12帧，每300帧临时包装一次主 Canvas 方法。
名称缓存实验退回：实测更慢，正式绘制仍使用原描边与填字，未保留试验缓存。

## 4 动画任务补充

不新增动作、视频或序列帧，帧数/源片/裁切不适用。所有角色和怪物继续由原绘制器实时绘制，25Hz逻辑与插值时钟不变。截图夹具只用于画面检查，性能窗口与30怪物采样运行正式逻辑。

## 5 制作指令

保持当前界面形态，只跳过完全相同的文字/属性/位置赋值；先测量再写入。目标变化、字体/内容换行、视口旋转和模式切换仍读取正式几何，不用常量高度代替。
