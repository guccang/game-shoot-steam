# 猫猫与载具弹药分区
依据：[项目约定](../../AGENTS.md)、[美术标准](../art-generation-standard.md)、[手机框架](../ui-foundation.md)。

## 目标与范围
功能交互修复，designCriterion：ammo-purchase-storage。将弹药铺含混的目的地下拉选择改成猫猫／载具两个明确入口。猫猫只出售通用子弹，载具出售车用弹药；通用子弹在两页各自入库。当前车在店旁时默认载具页，其他情况默认猫猫页。保留道具购买、制作费、库存上限与保存事务。

## 造型与技术
复用field-equipment中的ui-panel、ui-page、ui-section、ui-inset及ui-button；选中分类沿用ui-button--primary并设置aria-pressed。两按钮并排、正文自然滚动，触控至少44px，不新增样式或美术资产。展示车型货舱名、当前负重、明确收货位置；远处车辆禁用购买和制作。正式入口为src/ui/field-equipment.js中的renderShop。
不修改角色／载具模型、方向、动画、世界遮挡、碰撞和场景空间，因此这些资产和图层验收不适用；界面不新增计时器、画布、纹理缓存或PNG，沿用既有昼夜场景。只在打开／点击时重建列表，选中后恢复按钮焦点。

## 验收
通过，designCriterion：ammo-purchase-storage。

- 5项定向Node检查通过：购买／制作按目的地入库，猫猫与载具重量隔离，车载专用弹药不可在猫猫分类购买，缺少目标／远程补给／保存失败不扣款，车库停车入屋后可交易。
- 浏览器通过真实一秒入屋、点击售货员、分类切换与购买制作。3组库存状态、3种手机视口（320×568、390×844、844×390）×昼夜×两个分类共12组布局、1组车辆离店禁用检查通过，共16组截图。按钮至少44px，无正文横向溢出或弹窗出屏，当前分类与按钮收货目标一致。
- 刷新检查初次把“备用数量”当作总量，离店自动装填12发后断言失败；修正为备用加弹匣总量，单独续验存档与移动通过。标准炮弹5发、重型炮弹3发、通用子弹30发留在当前车，猫猫没有炮弹且移动系数为1。初次记录保留为result.txt，续验通过记录为persist-result.txt；不把初次失败标为全脚本通过。
- 实际视觉复核：output/playwright/ammo-purchase-storage/320-day-hand.png、390-night-vehicle.png；分类、收货车型和重量可辨，短屏沿正文正常滚动，夜间底板文字清晰。截图及其他视口、不可补给状态保存在同目录。
- 资源预算：无新PNG、字体、画布、动画或持续监听器；两分类复用原正式组件与弹窗事件代理。角色动作、建筑通行和场景资产未修改，相关动画／地形美术验收不适用。
- 未进行PNG替换，本次只是正式手机页面的分类与库存逻辑修复。
