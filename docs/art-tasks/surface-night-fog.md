# 地面夜间迷雾与近距交战

依据：[游戏美术资源生成标准](../art-generation-standard.md)、[AGENTS.md](../../AGENTS.md)。本任务于 2026-11-10 从美术生成任务单复制，制作前已记录同源地下雾幕、240 单位视野、170 单位远程上限、分层和验收计划；以下为完成后的字段与验收记录。

## 1 目标与范围

| 字段 | 内容 |
| --- | --- |
| 中文名称、稳定标识 | 地面夜间迷雾；`surface-night-fog` |
| 类别、当前阶段 | 场景动态特效与交战规则；程序动态效果开发 |
| 本轮目标 | 地面夜晚看不到远景，猫猫近处和真实路灯附近可辨；远程攻击随夜色收拢，白天恢复 |
| 动态与交互 | 跟随真实移动与镜头，沿现有 15 秒昼夜渐变；暂停不推进雾团表现时钟；沿用减少动态冻结；触摸与驾驶保留 |
| 数量和变体 | 一套共享雾幕，地下原光源、地面猫猫与路灯两种输入；结构差异来自真实光源位置和半径，不换色冒充新素材 |
| 保留项 | 猫真实连续帧、独立手枪与炮口、怪物动作、原场景配色比例、地下入口规则、碰撞、寻路与全部 UI |
| 制作路线 | 抽取地下 Canvas 雾幕为共享绘制器；不生成新位图或 SVG |
| 参考 | `src/rendering/mine-fog.js` 原正式画面、`docs/art-reference/environment-night.png` |
| 已确认效果 | 深绿遮蔽配柔边光池，保留暖灯、小范围色阶；不在 UI 上叠雾 |
| 后续精修 | 无本轮必需 PNG；动态透明合成继续由程序控制，无静态替换项 |
| 使用场景 | 地面森林与九寨沟；室内、矿区、独立靶场、秘境和阳台沿用原场景规则 |

## 2 造型与空间

| 字段 | 内容 |
| --- | --- |
| 主体剪影与主次 | 猫猫附近为主光池，路灯为次光池；远处被深绿迷雾遮住，5 个极淡雾团沿用地下表现 |
| 变体区别 | 地面猫圈半径 240；地下 138；路灯按原灯芯高度投影，地下矿灯及荧菇半径不变 |
| 地面衔接与邻接 | 覆盖正式地形、树冠、桥、建筑和实体；不改地面纹理，不增加可碰撞摆件 |
| 活动空间 | 原桥面、道路、入口及湖岸可通行范围不变，雾是视野规则，不是碰撞墙 |
| 光向与明暗 | 沿用场景材质受光；深绿雾幕覆盖远景，既有灯芯局部暖光保留 |

## 3 技术交付

| 字段 | 内容 |
| --- | --- |
| 逻辑尺寸 | 地面猫圈半径 240 世界单位；路灯沿用 145、火把沿用 112；地下各尺寸不变 |
| 像素尺寸 | 每个 Renderer 共用一张 `ceil(width/2) × ceil(height/2)` 视口画布，地下和地面复用，不随 DPR 增大 |
| 锚点、原点 | 猫猫世界位置 `(x,y-20)`；路灯 `(x+offset,y-height)`；最近周期镜像用于逻辑发现 |
| 分层 | 地面雾幕在正式世界、天气及色调之后，近身倒计时、装填提示及 DOM HUD 之前；地下分层不动 |
| 程序与图片职责 | 程序保留时钟、渐变、位置、灯光及攻击规则；既有图片和序列帧不变 |
| 替换接口 | `drawMineFog` 原调用接口与验收标识保留；共用 `drawVisionFog`，新地面入口 `drawSurfaceFog` |
| 透明背景 | 独立透明画布，destination-out 柔边光池；不包含不透明素材底板 |
| 碰撞与通行 | 无新碰撞；只限制发现、寻敌和远程有效射程，已经发出的弹丸保留发射快照 |
| 昼夜处理 | 白天无雾幕绘制；夜晚 opacity=.985，按正式夜色权重渐变，界面不参与合成 |
| 逻辑与数值 | 配置在 `src/config/surface-vision.js`；可见性与装备范围在 `src/world/surface-vision.js`；远程夜间取原射程 60% 和 170 的较小值，渐变期间线性混合；近战长度与控制器部署距离保留，控制器攻击范围单独收紧 |
| 来源与渲染器 | `src/rendering/vision-fog.js` 原样提取地下色阶和光池，地面调用 `src/rendering/surface-fog.js`，正式入口 `src/rendering/renderer.js` |
| 内存预算 | 单张画布，390×844 为 329160 字节；最多 16 光源，5 雾团；无全地图纹理、树木扫描和新增位图；白天仍可保留已分配画布，不重复分配 |
| 必需资源、失败 | 无新增素材依赖；使用现有正式资源加载机制，不以替换图片掩盖资源失败 |

## 2026-11-10 营地照明补充：制作前记录

用户反馈营地夜间能见度过低，要求路口补灯、扩大营地灯光、房屋窗户发亮。本轮仍为程序动态效果开发，新增子目标 `camp-night-lighting`：已购营地、邻里小院和五方友善营地降低雾密度，边界柔和回到野外迷雾；路口采用现有木制路灯形体，灯杆放路肩，不改变通行和碰撞；路灯光池扩大，住宅、仓库和维修车库按正式窗洞位置发暖光。建筑光源使用当前渲染实体，搬迁、修复、高层和未建成状态必须同步，不能在废墟或旧址留下灯光。保持原有独立猫、武器、载具动作及 UI。复用单张半分辨率雾画布，不增加全地图纹理。正式入口为 renderer、surface-fog、vision-fog、lighting 与新增 camp-window-lights；计划验收 320/390 手机昼夜、维修区、仓库、路口、窗光、营地边缘移动和无新增碰撞，完成后补充证据。
