# 金属探测与遗失装备任务单

依据 [美术标准](../art-generation-standard.md) 与 [AGENTS](../../AGENTS.md)。

## 目标与范围
开发阶段增加手机寻宝页、探测器、两辆坦克、两门主炮和两款发动机。沿用正式 Canvas / SVG 和手机底板，不新增位图；PNG 精修留待后续。线索来自实际邻居闲聊或委托对白，手机仅显示听过的线索与大致搜索区域。固定埋藏点每个存档仅领取一次，残骸交给正式维修救援。

## 造型与空间
「苔原守望」是窄车身、双履带、后置行李架的青绿巡护坦克；「琥珀堡垒」为宽履带、斜角侧裙与前置双牵引钩的赭金重坦。保持车头朝下俯视角；履带独立滚动，底盘不旋转冒充动作。主炮「长枝穿甲炮」使用细长炮管与双支撑，「蜂巢散射炮」使用短粗多孔炮口；炮管后坐独立于炮架。发动机图标分别为竖列散热片与双圆缸头，探测器为握柄、显示表与椭圆线圈。

## 技术交付
载具约112×82世界单位，中心为驾驶位；前后层分别沿用 drawVehicleTracks / drawVehicleArmor，投影在后层。主炮局部朝右，正式瞄准旋转与炮口接口不变；装备图标64×64视框。寻宝页使用44px以上触控按钮、格子、状态与实时探测强度条，数字及数量由程序维护。固定点不阻挡通路，不在未得到线索时显示地图精确坐标。无独立动画计时器，无新图集与缓存。

## 参考与保留
参照 src/rendering/vehicle-models.js、red-wolf.js、vehicle-armaments.js 和 inventory-icons.js。保留猫猫视频帧、武器独立动作、战斗、碰撞、世界环绕坐标和暂停规则。战利品载重、维修费用及换装共享正式逻辑。

## 验收计划
检查手机窄屏/长屏/短横屏、正式昼夜场景与车头方向；验证线索记录、探测距离、固定点唯一性、取消/失败不吞货、载荷不足提示、部件换装守恒、损坏坦克维修和读档。正式 designCriterion 为 metal-detector-treasure；验收结果完成后追加。

## 验收结果

- 通过：13项寻宝专项验证涵盖固定点可达、唯一奖励、只听过才记录、不同猫猫的任务替代来源、工具购买计重、报废车耐久与维修报价、远程/满载领取拦截、保存失败回滚、跨车换装守恒、原车减载约束、已装填弹药重量，以及新炮真实开火与断供停止。
- 相关旧载荷/供给/合同回归35项通过。两项旧维修断言仍要求停车到北广场，在未修改main上复现同样失败；当前正式行为是修好停在维修车位，不改回旧行为。
- 手机实机30个检查点通过，页面异常为零：空白手记、六次真实电话、柜台购买、区域导航、探测挖掘、满载提示、六件唯一物品、实际工坊换装、完整救援维修、刷新保留。320×568、390×844、844×390均无底板越界，短屏内容可滚动。
- 动作补充通过：两种坦克在白天和夜间分别实际消耗炮弹、触发炮管后坐并复位；履带随真实位移推进，停车/下车保留相位。保留猫猫真实动作与独立手持武器，车头仍为朝下俯视，两种履带宽度、行李架、侧裙和拖钩可辨。
- 视觉已查看：窄屏手记、横屏底板、探索部件图标、装配重量与损坏百分比、两种出土残骸、昼夜战斗及后坐连续状态。图标为64×64 SVG，车型与主炮由正式 Canvas 绘制；未新增运行位图、图集或独立时钟。
- 实机证据：`output/playwright/treasure/` 中 `result.txt`、`combat-result.txt`、`journal-320.png`、`journal-844.png`、`cargo-full.png`、`honeycomb-installed.png`、`collected-twin-heart.png`、两种残骸昼夜截图，以及 `hull-9-*`、`hull-10-*` 开火/复位/移动截图和录像。早期失败截图保留用于排查，最终结果以两份结果文件为准。
- 正式入口：`src/ui/treasure.js#createTreasure`、`src/rendering/treasure-equipment.js`、`src/rendering/visual-review.js#inspectTreasure`；绑定 `designCriterion: metal-detector-treasure`。内容表校验与修改文件语法检查通过。结论：本轮开发通过，PNG精修为后续阶段。
