# 地下移动卡顿修复任务单

执行依据：[游戏美术资源生成标准](../art-generation-standard.md)、[AGENTS.md](../../AGENTS.md)。本单按[标准任务单](../art-generation-brief.md)填写。

## 1 目标与范围

| 字段 | 内容 |
| --- | --- |
| 名称与稳定标识 | 地下移动性能 / mine-motion-performance |
| 类别与阶段 | 正式地形动态表现和手机 HUD 性能修复 |
| 目标 | 步行和矿车移动跨格时减少长帧，有怪物时仍流畅跟随 |
| 数量、变体 | 不新增地形种类或武器、角色变体 |
| 保留项 | 原 16 单位三角地形精度、岩壁与水岸、开掘效果、脚底与镜头锚点、角色真实连续帧、矿车轮毂与武器动画 |
| 制作路线 | 原 Canvas 程序路径优化；本次无 imagegen、SVG、PNG 或离屏位图 |
| 参考 | 用户矿车移动截图、正式地下昼夜画面、原 mine-cart-rider-stability 验收 |
| 使用场景 | 天然洞厅、开掘矿道、桥面、矿车及地下战斗 |
| 后续精修 | 不适用；本次不替换静态资源 |

## 2 造型与空间

主体剪影、主次、地面衔接、邻接景观和光向完全沿用现有地下美术。优化只抵消相邻三角面的内部边，保留外轮廓、孔洞与原始顶点位置。原边界岩层和开掘碰撞不变，不以减少景观数量或冻结水流动画换取性能。

所有已有走道、桥面、轨道及车体通行方式不变。地图尺寸、比例、森林绿描边和昼夜配色不变。

## 4 动画补充

角色同源待机/移动帧、枪械后坐、车轮、怪物、流水与蒸汽的时钟、尺寸和锚点不变。矿车仍按 25Hz 逻辑和显示插值行驶；暂停和停车规则不变。

HUD 数值与小地图每 100ms 刷新，工具、停车、房间、弹窗状态和视口尺寸变化立即刷新。只限制 DOM 更新频率，不降低 Canvas 或逻辑帧率。

录像：output/playwright/mine-motion/rider/video/。实际镜头连续采样和帧耗时见同目录 comparison.json 与 rider-summary.json。

## 5 生成指令

未调用 imagegen：本次优化正式运行时路径与查询，不生成或编辑美术资源。无需新源视频或 PNG 精修；旧动作来源、独立部件及身体合同继续适用。

## 7 性能与针对性检查

在本机同一390×844隔离浏览器、相同种子和矿车路线采样，每个阶段150个实际RAF。浏览器调度和当前位置会影响结果，数据不是其他设备的帧率保证。

| 指标 | 修复前 | 最终 |
| --- | ---: | ---: |
| 无怪矿车绘制 P95 | 53.1ms | 7.9ms |
| 有怪矿车逻辑平均 | 26.05ms | 2.02ms |
| 有怪矿车绘制 P95 | 63.0ms | 8.1ms |
| 有怪矿车 RAF 平均 | 81.48ms | 21.00ms |
| 有怪矿车 >34ms 长帧 / 150次 | 141 | 8 |
| 夜间矿车 RAF 平均 | 75.35ms | 17.32ms |
| 步行 RAF 平均 | 87.42ms | 16.64ms |
| 步行 >34ms 长帧 / 150次 | 150 | 1 |

修复前后完整记录及中间迭代保留在 comparison.json。曾发现仅分块仍有较多帧波动，继续完成轮廓合并与HUD更新优化后再验收；没有以降低地形精度掩盖卡顿。

针对性规则检查：首次48项全部通过（地下武器、地形、边界、矿车插值和5项缓存回归）；新增轮廓合并后重跑6项缓存/轮廓用例全部通过，去重合计49项通过。随后只进行与改动直接相关的浏览器像素、HUD和矿车验收，未运行全量 npm test。

浏览器：性能采样600次、像素比较8组、矿车与手机验收通过，未发生页面异常。脚本默认遵循当前浏览器服务地址；本轮4175已有服务，使用4187独立开发服务。
