# 小屋仓库美术任务单

依据：[美术标准](../art-generation-standard.md)、[统一合同](../../AGENTS.md)。按美术生成任务单记录本轮开发范围。

## 1 目标与范围

小屋仓库 `warehouse`，新增营地建筑、室内分类箱和存取页面。采用现有 Canvas 建筑主体、物品 SVG 和统一手机底板完成动态交互开发。门前站定一秒进入，管理员柜台打开存取，出口一秒离开。保留猫连续动作、独立武器、怪物和载具正式绘制。参考现有家具小铺与巡林小屋，不使用新位图；PNG 材质精修属于后续阶段。

## 2 造型与空间

仓库位于巡林小屋西侧、北停车场东侧，底座世界坐标 `(285,300)`，144×124。草木绿山墙顶、奶油木墙、左侧原木与右侧交叉加固货箱区别于住宅和家具橱窗。门前泥地院落接主路，中央门槛开放；原占地树移除，墙体、耕地排除和树冠净空共用正式配置。光向、落影和窗光沿用营地建筑。室内三种分类箱贴侧墙，管理员和柜台居中，入口到柜台的走道保持开放。

## 3 技术交付

外部锚点在底座中央，世界深度队列裁剪与排序；实体墙矩形相对锚点 `[-67,-88,69,5]`，进入点 `(285,322)`。室内 360×380，分类箱碰撞 65×42；UI 图标使用正式物品目录，48px 容器，按钮使用统一 44px 最小触控区。新增位图、图集、解码和持久缓存均为零。数值、数量滑条、负重及进入计时由程序维护。

## 4 动画任务补充

建筑和货箱为静态场景，无新增动作帧；猫身体、武器、怪物、车轮等沿用正式运行时。门前/出口计时保持一秒并随移动取消；存取页面暂停场景。无需源视频、图集裁切或新动画时钟。

## 5 生成指令

本轮延伸既有程序绘制建筑和 SVG 物品目录，不调用 imagegen。正式入口为 `src/rendering/warehouse.js#drawWarehouse`、`src/rendering/building-architecture.js#drawBuildingArchitecture`、`src/rendering/workshop-interior.js#drawWorkshopInterior`。独立 UI 为 `src/ui/warehouse.js`，验收入口 `src/rendering/visual-review.js#inspectWarehouse`，对应 `designCriterion: warehouse-building`。后续 PNG 替换保持尺寸、锚点、稳定 ID 与交互。

## 6 验收记录

- 系列与空间：实机外景与现有小屋、家具店、角色、载具和怪物同屏核对，原木与加固货箱可辨；门口与北停车场通路检查通过，墙面不可穿越，仓库范围不可耕种。中央室内通道无遮挡，货箱与柜台保留实体。
- 动态交互：正式一秒入室与一秒出门通过；点击管理员打开页面，木材全部入库、弹药滑条选择、种子入库、载具弹药往返、取消与刷新保留均通过。19 个浏览器检查点，无页面异常。
- 库存事务：仓库专项 4 项与木材直接回归 7 项共 11 项通过，覆盖物品守恒、减负、上限、超载确认、远车/维修车权限和保存失败回滚。
- 手机布局：320×568、390×844、844×390 短横屏及 900×1280 既有容器，外景昼夜和仓库面板无视口越界；数量滑条与操作按钮清楚，使用统一底板和触控尺寸，不新增桌面布局。
- 视觉证据：[白天外观](../art-reference/warehouse-day.png)、[夜晚外观](../art-reference/warehouse-night.png)、[内部柜台](../art-reference/warehouse-inside.png)。完整实机截图、交互录像及检查结果在 `output/playwright/warehouse/`，包括 `wood-quantity.png`、`vehicle-ammo.png` 与 `video/`。
- 资源预算：无新增运行位图、图集或预生成缓存；建筑按视野裁剪，静态物件沿用正式深度队列。无需新增帧图集或源视频；本轮未修改身体或独立武器动画。
- 开发结论：通过。PNG 精修替换为后续阶段，保持当前已确认的空间、轮廓和接口。

## 7 仓库格子与拖拽改版（制作前约定）

目标：背包／附近载具货舱与仓库以两个库存格子区同时显示，物品图标角标显示完整数量，分区标题显示类别数和物品总数。拖图标到另一侧后以滑条确认数量；区域外放手、取消和中断不扣货。两区分别滚动，不设固定格子上限，空区保留投放位置。保留木材建设共用库存、弹药分流、种子仅背包、负重确认和保存事务。

沿用背包正式 SVG 图标、森林绿描边和统一手机底板，图标 44px、拖动触控区域至少 48px；无新位图、图集、世界坐标或动作修改。浮动格子在当前弹窗上层跟随指针，数量确认使用独立紧凑底板，短屏检查实际投放空间。正式入口 `src/ui/warehouse.js`、`src/ui/warehouse-drag.js`，继续使用 `inspectWarehouse` / `warehouse-building` 验收。结果与截图在完成实机检查后补充。

### 格子改版验收结果

- 通过：正式手机页面显示物品图标、完整堆叠数量和库存总数；只有实际持有物品生成格子，无固定格子数量。两区独立滚动，竖屏上下排列，短横屏左右排列，分类和目标区域始终可用。
- 原生触摸拖拽通过：木材、弹药和种子入库，载具弹药取回正确货舱，同区松手和触摸中断不转移；点选仍可打开滑条。触摸结束后再开启数量层，避免兼容点击穿透和后续取消不响应。
- 4 项仓库事务测试与 33 个浏览器检查点通过，页面异常为零。覆盖滑条数量、取消、满载风险提示、关闭恢复游戏、正式一秒进出和刷新持久化。
- 实际检查 320×568、360×640、390×844、430×932、844×390 与 900×1280 既有手机容器；已查看窄屏格子、横屏格子／数量层、满载确认和昼夜正式场景。没有新增桌面专用布局。
- 证据：`output/playwright/warehouse-drag-grid/` 下 `wood-stock.png`、`panel-320.png`、`panel-844.png`、`quantity-844.png`、`overload-warning.png`、`exterior-390-day.png`、`exterior-390-night.png`、`inside-night.png`、`result.txt` 和交互录像。对应 `designCriterion: warehouse-building`；`inspectWarehouse` 同时提供两区格子数、库存总数和数量层状态。
- 资源预算：新增运行位图与图集为零，浮动格子仅拖动期间创建并在结束／中断时释放，无新动画时钟或世界实体；角色、武器、怪物及载具绘制保持原合同。
