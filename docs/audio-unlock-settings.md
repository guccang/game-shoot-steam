# 声音启用与设置试听修复

## 原因与改动

- 缺失声音偏好时原来默认关闭；首次点击进入也不会开启。现在默认开启，首页在用户手势前仍不创建设备；明确保存的静音选择继续保留。
- 打开设置会暂停游戏，原来音乐也停止，音量调整没有试听。增加独立的设置音乐试听状态，战斗、发动机仍暂停；调整音效后播放短提示音。静音时明确显示“声音已关闭”并禁用音量滑块。
- 移动端解锁从 pointerdown 改为捕获阶段的 pointerup、click 和 keydown，避免触摸按下尚未获得播放权限或场景阻止冒泡。开关自身仍由点击直接解锁。
- 弹窗开关立即同步音景，首页没有战场帧循环时也能试听，关闭后停止。
- 原音乐 WAV 可加载解码；桌面开启后能正常播放，未发现音色资源损坏。秘境实际战斗同样使用 playing 状态，无需额外修改。

## 相关验收

- `node --test tests/audio.test.mjs`：20 项通过，覆盖默认解锁、静音保存、分轨调音、设置试听、暂停/后台、循环释放、枪声和换弹路由。
- `tests/audio-unlock-settings-browser.cjs`：隔离端口 4285，1280 桌面点击和 390 手机触摸通过。使用正式 AudioContext、音乐文件和枪声，旁路 AnalyserNode 测量输出，不替换正式音频。
- 桌面/触屏进入后音频峰值约 0.159 / 0.162，枪声峰值约 0.607 / 0.602；静音及双音轨归零后峰值为 0。音乐增益从约 0.999 调至 0.103，音效试听有非零输出。
- 刷新保留关闭状态、音乐 0%、音效 80%，且静音时不创建设备；重新开启恢复输出。首页设置试听有输出，关闭后归零；浏览器错误为空。
- 截图：`output/playwright/audio-unlock-settings/settings-1280.png`、`settings-390.png`。状态与百分比清楚，未出现遮挡。
- 本次仅声音逻辑与设置反馈变更，未修改美术资源或场景绘制。未运行全量测试；自动化验证覆盖 Chromium 桌面与触摸模拟，不代表实体设备扬声器或系统音量验收。
