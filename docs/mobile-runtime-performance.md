# 手机持续运行负载优化记录

2026-10-27。问题反馈：华为 Mate 50 Pro，Chrome，游玩约 30 分钟后发热并下降到约 17 FPS。没有连接该手机，不能将电脑浏览器结果当作真机温度或持续帧率结论。

## 修改与边界

- `src/platform/frame-loop.js`：完整游戏循环上限 60 Hz，60/90/120/144 Hz 屏幕共用真实时间差；跳过高刷多余回调时累计时间，长帧仍沿用原 50 ms 安全上限。后台回调不执行场景工作，恢复不补跑积压帧。
- `src/physics/motion.js`：没有刚体、没有残块或没有有效时间步时直接返回，不建立数千棵树的空间索引。非空战斗保留原碰撞与连锁冲量算法。
- `src/combat/perception.js`、`targeting.js`、`src/core/game.js`：以保守包围盒排除远目标，再使用原精确循环世界距离和视野规则；普通寻敌用单次扫描保留最近对象、同距顺序、敌人优先及持续交战资格。穿透武器保留原射线解算。
- 诊断版本更新为 `2026-10-27-mobile-runtime-1`；近期严重战斗尖峰保留一分钟提示，并提供窗口焦点与焦点切换事件。没有新增常驻缓存、美术资源、画质档位或改变武器数值。

## 验证

针对性测试文件：`mobile-runtime.test.mjs`、`mobile-performance.test.mjs`、`modules.test.mjs`、`targeting.test.mjs`、`combat-perception.test.mjs`、`performance-monitor.test.mjs`。共 49 项通过，没有运行全量测试。

调度测试以人工时钟分别模拟四种刷新率的 30 分钟，均执行 108000 次更新，累计模拟时间为 1800 秒；这不是手机运行 30 分钟的热测试。覆盖后台、恢复、卡顿、重复启动、销毁、250 组新旧寻敌对象对比、射程边缘和多圈地图镜像。

两项旧移动性能测试在主分支也失败，原因是地图扩张后仍写死旧边界。夹具已改为当前 `WORLD` 和 `RAIN_CELL` 尺寸；完整物理等价与雨场周期检查通过。

同一 Node 进程、同一 3865 棵树场景和正式 390×844 镜头数据，预热后交替执行旧版与新版普通寻敌，5 轮、每轮 1000 次：单次耗时中位数约 **0.249 ms → 0.133 ms**。这是局部 CPU 工作量对照，不能换算为整机 FPS 或温度降幅。空物理调用已通过代理集合断言确认不再读取树木。

正式浏览器在 `http://localhost:4175` 运行：390×844、DPR 2、CPU 4 倍降速下进行昼夜走位；另以 320×568、390×844 触屏视口检查手枪、狙击、车载机枪。未发现的屏外敌人不消耗弹药，目标入屏后由正式武器击杀。昼夜截图检查人物、武器、载具、怪物、环境与 HUD。浏览器前后整帧计时波动较大，**未据此确认整体帧率提升比例**。

本地证据保存在 `output/playwright/thermal/`（前后记录、最终微基准、昼夜截图）和 `output/playwright/combat-perception/`（普通、狙击和载具的入屏/屏外截图）。性能采样入口为 `tests/mobile-runtime-browser.cjs`；该脚本只允许 4175 端口，应在隔离的 Playwright 会话运行。

## 真机复测

刷新部署后的游戏，确认性能报告版本为 `2026-10-27-mobile-runtime-1`，在同一玩法连续运行约 30 分钟。仍有低帧率时，保留设置中 Debug 的性能报告，使用逻辑、绘制、回调外等待和缓存数据继续定位；当前没有足够证据将原问题完全归因于温升或排除真机内存压力。

## 用户补充的兽潮日志

用户在开发期间提供 `forest-performance (1).json`。记录的设备是 Windows Chrome、DPR 1，版本仍为旧版；它不能替代 Mate 50 Pro 的半小时温升测试。

- 运行时间约 274 秒处，回调间隔 4165 ms，回调外等待约 4144 ms，当前帧工作约 24 ms，场上 22 个敌人。
- 对应长动画帧为约 4160 ms，脚本约 24 ms，`blockingDuration` 为 0；期间诊断定时器还执行了约 2.6 ms 的保存。因此没有证据将这 4 秒归因于同步寻敌或碰撞循环，也不能仅凭回调外等待断定 GPU 故障。
- 导出前最近 120 个战斗帧已恢复到约 58.8 FPS，旧摘要显示“暂无明显慢帧”，但尖峰列表仍保存严重停顿。
- JS 堆约 49 MiB，地面缓存 61/64 块、约 61 MiB，导航缓存 4096/4096，无画布上下文丢失。这是一份快照，不足以证明或排除内存泄漏。

新增回归复现“停顿4.165秒→恢复超过120帧→打开设置导出”，当前 FPS 与近期严重停顿分开显示。诊断浏览器入口为 `tests/mobile-runtime-diagnostics-browser.cjs`，使用人工尖峰验证 320/390 手机宽度、报告字段与焦点事件，不人为制造真实4秒死循环。
