# 导航光点间歇消失：原因与改动

## 原因

原缓存只允许玩家直线接到 128 世界单位内的最近路点或下一点。在树旁、围栏拐角或稍微走偏后，直连失败便清空整条路线，重新分帧搜索；搜索结束前没有光点。长途搜索期间玩家继续移动，也可能使刚得到的路线再次失效。

另外，故事和邻里缓存原先在树数组或树木数量变化时整体重建。远处砍树、再生也会打断当前导航。显示端又先截取距玩家 640 单位内的前 24 个点，再做镜头裁剪，导致宽视野或偏移镜头下仍在屏幕内的后续路段没有光点。

## 当前行为

1. 对当前目标计算并缓存完整路线；沿路移动不重算全程。
2. 在实际镜头内选择距玩家最近的主路线点。附近能直连的短边直接复用；遇到树或墙角时用局部 A* 绕行接回主路，完成的接入段也继续复用。
3. 局部搜索期间保留已知主路线光点，不绘制未经碰撞验证的连接线。
4. 以镜头世界宽高的较大值作为“一屏”距离；玩家距离整条主路超过该距离后，从当前位置重算全程。目标、地图、通行能力变化，新障碍阻断路线或局部搜索确实无法接回时，也会重新规划。
5. 远处树木变化只刷新空间索引，不清空主路。新障碍接近缓存路段才使路线失效。
6. 绘制时按真实镜头筛选光点，再限制同屏数量；维持原 36 单位间隔和箭头样式，每路线最多 96 点。接入后的后续主路仍按终点锚定，不随玩家移动整串滑动。

主搜索与局部搜索每帧最多推进 256 个微步骤或约 1.5 毫秒，同帧重复读取不重复推进。局部搜索限制在起点和接入点周围 96 单位的矩形内、最多 2048 个节点。世界镜像由最近路点决定，避免长途行走超过起点半张地图后突然换到错误镜像。

暂停、对白和关闭寻路仍隐藏光点，但保留会话内已验证路线；恢复时重新核对目标、角色、地图与通行能力。抵达、战斗试射、任务切换和主动导航意图仍沿用已有规则；无路线或目标不可达时不会伪造穿墙直线。召唤物保持原跟随缓存，不改其行为。

## 2026-10-29 清缴接单与恢复修复

接单选点原本已经同步验证完整路线，却只保留终点；显示端从零分帧搜索，造成数秒空白。现在选点交付逐段验证的短边，仅在保存成功后、界面事件刷新前移交给正式导航。首帧直接复用，路线不进入存档；失败保存、新游戏、目标或通行条件变化均不能继承错误路径。清缴场地仍要求普通步行可达，红狼穿树能力变化也会使显示缓存重新校验。

暂停、对白及开关恢复不重算同一条路径；远处停车访客轮换不清空主路，新车体靠近缓存线段才使其失效。重新搜索继续遵守256微步骤/1.5毫秒的每帧预算。缺木材修复任务仍指向原树，但行走终点选择树干外可站立的脚底位置。

本轮24项导航回归通过。浏览器真实接单首帧16个光点、主搜索0次；设置暂停恢复同样立即显示16点；触控移动约72.93世界单位（约7.3米），记录内无空白帧。320×568、390×844与1100×844既有竖版容器昼夜同屏共6组，光点5–7个，各段碰撞检查通过，无页面错误和横向溢出。夜间光照权重确认为1、白天为0。截图及交互录像位于 `output/playwright/navigation-route-resume/`。

开发期间主分支加入红狼穿树能力，合并后将 `treePass` 纳入缓存通行签名，并保持接单选点按普通步行验证。追加执行9项受影响导航回归与4项红狼碰撞/下车/读档回归，13项全部通过，见同目录 `merge-regression.txt`；未执行全量测试。
