# 25Hz逻辑与60Hz渲染

版本：`2026-10-27-fixed-logic-25-v2`。

正式应用现在使用两个节拍：RAF至多60Hz调度绘制，逻辑累积真实秒数后按40ms更新。17FPS时一帧通常处理1～2个逻辑步，不把游戏速度降成17/25；严重卡顿单帧最多补两步，剩余整步丢弃并计入`droppedLogicSeconds`，避免一次恢复执行几十步。隐藏/恢复与首页清空余量。

表现对象插值上一与当前逻辑状态，平滑位置、最短弧朝向、身体连续时钟、后坐、弹道、伙伴和载具部件。正常情况下有约一逻辑步（40ms）的表现延迟。真实身体图集仍按原24FPS连续帧播放，未生成虚构帧。离散生命/弹药与碰撞继续使用权威状态；出生、销毁、暂停、切地图与大位移传送不跨状态插值。静态树林不复制。

手持枪、浮游炮、伙伴背枪及车炮保留射击冷却余量；高速武器可在同一40ms步内执行多次正式扣弹/发射，无目标、转向、装填期间不囤积开火。物理已有细分步进与弹道扫掠继续生效。

日志新增每个渲染帧的`logicSteps`、`logicHz`、`renderTargetHz`、`interpolationAlpha`、`droppedLogicSeconds`；汇总中的`fps`为绘制帧率，`logicFps`为实际逻辑调用频率。`render.interpolation`单独计时，包含在总渲染成本中，不应重复加总。

## 加速问题与验证

开发时曾将秒单位的帧间隔命名为`elapsed`，被同一回调内部的日历毫秒变量遮蔽，导致每帧都执行两次逻辑。正式浏览器验证发现逻辑频率约100Hz，与用户反馈的加速相符。已将帧间隔明确命名为`frameElapsed`，独立传入固定逻辑时钟；诊断版本提升到v2，浏览器测试增加现实时间和模拟时间对照。

- `tests/fixed-step.test.mjs`：10项通过，包括半小时60/90/120/144Hz输入均为108000次绘制、45000次逻辑，17FPS保持25Hz、严重停顿、后台恢复、插值不改权威状态、实体身份/生命周期、环面/角度、诊断频率、手持及挂枪高速射速。
- 正式浏览器390宽实际10秒走位、开火、起停与设置暂停；320/390/1200宽昼夜同屏。白天逻辑24.78Hz、绘制53.09FPS；夜间逻辑25.14Hz、绘制59.15FPS。264/284个采样帧在无逻辑更新时仍有不同的呈现位置。录制、截图与JSON结果保留于`output/playwright/fixed-step/`。
- 核心分帧/诊断/动画/后坐/车轮检查48项，其中46项通过、2项旧失败；另一次相关武器检查也保留完整结果。合计9项既有失败已在主分支独立重现：浮游炮弹道来源快照1项、弹仓2项、伙伴挂载1项、车辆购买/工坊3项、后坐重生1项、车轮旧地图宽度1项。详情见`output/playwright/thermal/fixed-step-*-baseline*.log`；未将这些旧失败算作通过，也未借本次时钟修改改变交易规则。

本次减少完整逻辑调用频率，但增加少量表现插值开销，不能据此保证GPU受限时恒定60FPS。Mate50Pro/Chrome运行30分钟后的温度与掉帧仍需真机复测。刷新页面后在性能日志确认v2版本，已打开的旧页面不会自动替换正在运行的ES模块。
